# 프론트 디자인 작업 가이드라인

> 대상: `nurse_rostering_front/roster_front` 의 UI/디자인 작업.
> 핵심: **전체 컬러·스타일을 깨지 않는 선에서, 스킬을 찾아 디자인을 적용한다.**

## 1. 원칙 — 기존 컬러/스타일을 깨지 않는다 (최우선)

새 화면·컴포넌트를 만들거나 기존 UI를 손볼 때, **전역 디자인 시스템이 단일 진실(SSOT)**이다.

- **컬러**: 기존 팔레트/디자인 토큰/테마 변수만 사용. **임의 hex·새 색 체계 도입 금지.** (필요하면 토큰 추가를 먼저 합의)
- **컴포넌트**: 기존 컴포넌트 라이브러리를 **우선 재사용**. 같은 역할의 컴포넌트를 새로 만들지 않는다.
- **타이포·간격·라운드·섀도**: 기존 spacing/typography/radius/shadow 스케일을 따른다.
- **톤**: 기존 제품 톤 유지(예: AgentChatWidget Claude 톤 리라이트 기조).
- **상태·반응형·접근성**: 다크/라이트, 반응형 브레이크포인트, hover/disabled/loading 등 기존 규칙 준수.

> 한 줄: **"예뻐 보이게"보다 "기존과 일관되게"가 먼저.** 일관성이 깨지면 디자인은 실패다.

## 2. 프로세스 — 스킬을 찾아서 적용

1. 새 UI/디자인 작업이 필요하면 **`find-skills`로 적절한 디자인/UI 스킬을 먼저 탐색**한다. (설치: `~/.agents/skills/find-skills`)
2. 스킬이 제안/생성한 결과를 **그대로 붙이지 않는다.** 반드시 §1 원칙(기존 토큰·컴포넌트·톤)에 맞게 **리스타일링**한 뒤 적용.
3. 스킬 산출물이 새 색/폰트/컴포넌트를 끌고 오면, **전역 시스템 값으로 치환**한 후 반영.

## 3. 작업 체크리스트

- [ ] 기존 **팔레트/디자인 토큰**만 사용했는가 (새 색/그림자/폰트 미도입)
- [ ] 동일 역할의 **기존 컴포넌트를 재사용**했는가 (중복 신규 생성 X)
- [ ] spacing/typography/radius 등 **기존 스케일** 준수
- [ ] 다크·라이트 / 반응형 / hover·disabled·loading 등 **상태 규칙** 준수
- [ ] 스킬 산출물을 **전역 토큰에 맞게 치환·리스타일** 했는가
- [ ] 변경 전후 **시각 회귀** 확인 (예: modalGate 등 기존 회귀 패턴)
- [ ] `tsc --noEmit` 통과

## 4. 하지 말 것 (anti-pattern)

- 스킬/외부 템플릿의 색·폰트·컴포넌트를 **검수 없이 그대로 도입**.
- 한 화면만을 위한 **일회성 색/스타일 하드코딩**(토큰 우회).
- 같은 기능의 **컴포넌트 중복 생성**(예: 또 다른 버튼/모달).
- 전역 테마·토큰 변수 **임의 변경**(다른 화면 파급).
