# 근무표 플랫폼 — 기능 구조 요약

> 최종 갱신: 2026-04-06  
> 근거: 코드 직접 분석 (roster-back `app/`, roster_front `src/`)

---

## 1. 프로젝트 개요

병원 간호사 근무표 자동 생성 플랫폼. 수간호사(HN)가 근무 규칙과 인력 구성을 설정하면, CP-SAT 최적화 엔진이 법규·내규·개인 선호를 모두 반영한 월간 근무표를 자동 생성한다.

### 핵심 흐름

```
조직/인력 구성 → 규칙 설정 → 선호 수집(Wanted) → 근무표 생성(CP-SAT) → 검토/수정 → 발행
```

---

## 2. 3층 구조 매핑

모든 기능은 아래 3개 층 중 하나에 속한다.

| 층 | 목적 | 설정 주체 | 변경 빈도 |
|----|------|-----------|-----------|
| **Layer 1: 조직/권한/구조** | 누가 어디에 속하고 무엇을 할 수 있는지 정의 | 마스터 관리자(ADM), 수간호사(HN) | 낮음 (분기~연 1회) |
| **Layer 2: 근무표 생성 규칙** | 어떤 규칙으로 근무표를 만들 것인지 정의 | 수간호사(HN) | 중간 (월 1회 이하) |
| **Layer 3: 운영 편의 및 예외 처리** | 선호 수집, 일상 운영, 공유, 분석 | 수간호사(HN), 일반 간호사 | 높음 (매월/매일) |

| Layer | 기능 수 | 핵심 키워드 |

| **L1: 조직/권한/구조** | 8개 (1-1 ~ 1-8) | Group, Team, Nurse, RBAC, Auth, Preceptor |

## 5. 카테고리 분류 근거

### 왜 이 3층 구조인가?

1. **L1은 "틀"이다** — 어떤 조직이 존재하고, 누가 무엇을 할 수 있는지. 이것이 없으면 나머지가 의미 없다.
2. **L2는 "규칙"이다** — 근무표 자동 생성 엔진이 참조하는 모든 제약과 정책. 이것이 없으면 생성 품질이 보장되지 않는다.
3. **L3은 "운영"이다** — 실제 매월 반복되는 업무 흐름. 선호 수집 → 생성 → 검토 → 발행의 사이클.

### 설정 적용 우선순위 (높음→낮음)

```
법규 하드 제약 (L2-4)
  > 내규 소프트 제약 (L2-5)
    > 그룹 정책 (L2-2, L2-3, L2-6, L2-7)
      > 팀 정책 (L2-9)
        > 개인 예외 (L3-3 FixedWanted)
          > 개인 선호 (L3-2 Preferences)
```
