# Layer 2: 근무표 생성 규칙 관리

> 이 문서는 "어떤 규칙으로 근무표를 만들 것인지"를 정의하는 기능들을 다룬다.  
> CP-SAT 솔버가 직접 참조하는 제약·정책·설정이며, 설정 품질이 곧 근무표 품질이다.

---

## 2-1. 근무코드(Shift) 설정

### 기능 설명
병동에서 사용하는 근무 유형(Day, Evening, Night, Off, Mid 등)을 정의한다. 각 코드에 시간, 색상, 자동스케줄 포함 여부 등을 설정한다.

### 이 기능이 필요한 이유
- 병원마다 근무 유형이 다르다 (2교대/3교대, 미드 근무 유무 등)
- 근무코드가 없으면 인력배치, 선호 수집, 근무표 생성 모두 불가능
- 휴가, 공가, 연차 같은 특수 코드도 여기서 정의

### 코드 위치

| 구성 요소 | 경로 |
|-----------|------|
| Router | `app/routers/shifts.py` |
| Service | `app/services/shift_service_mssql.py` |
| DB Model | `app/db/models.py:Shift` |
| Frontend | `ConfTab1` (근무코드 설정 탭) |
| API 호출 | `src/api/req.ts` (`/shifts/*`) |

### API 상세

| Method | Endpoint | 권한 | 설명 |
|--------|----------|------|------|
| GET | `/shifts` | 인증됨 | 그룹의 근무코드 목록 |
| POST | `/shifts/add` | HN | 코드 추가 |
| POST | `/shifts/update` | HN | 코드 수정 |
| POST | `/shifts/remove` | HN | 코드 삭제 |
| POST | `/shifts/move` | HN | 순서 변경 |
| GET | `/shifts/template-download` | 인증됨 | 엑셀 템플릿 |
| POST | `/shifts/upload-validate` → `/upload-confirm` | HN | 엑셀 업로드 |
| GET | `/shifts/available-imports` | HN | 다른 그룹에서 가져올 수 있는 코드 |
| POST | `/shifts/import-to-group` | HN | 다른 그룹의 코드 가져오기 |

### 핵심 속성

| 속성 | 타입 | 설명 | 솔버 반영 |
|------|------|------|-----------|
| `shift_id` | VARCHAR(10) | 코드 (D, E, N, O, M 등) | O — 솔버 변수 식별자 |
| `name` | VARCHAR(20) | 표시 이름 | X |
| `color` | VARCHAR(10) | UI 색상 | X |
| `start_time` / `end_time` | Time | 근무 시간 | 부분적 — duration 계산 |
| `type` | VARCHAR(10) | "근무" 또는 "휴무" | O — off vs work 구분 |
| `auto_schedule` | INT | 0/1 | O — 0이면 솔버에서 제외 |
| `is_weekly_off` | TINYINT | 주휴 전용 코드 | O — 주휴 배정용 |
| `show_in_preference` | BOOL | 선호 UI에 표시 | X — 프론트 전용 |
| `sequence` | INT | 표시 순서 | X |

### ShiftManage 연동
근무코드 추가/삭제 시 `ShiftManage` 테이블의 `codes` 배열에 자동 동기화:
- D → slot 1, E → slot 2, N → slot 3, M → slot 5
- 코드 추가 시 해당 슬롯의 codes 배열에 추가
- 코드 삭제 시 codes 배열에서 제거

### 연관 기능
- **2-2 인력배치**: 근무코드별 필요 인원 설정
- **3-2 선호 제출**: `show_in_preference=True`인 코드만 선호 UI에 표시
- **3-4 근무표 생성**: 솔버가 `auto_schedule=1`인 코드만 배정 대상으로 사용

### 현재 코드상 제약사항
- `shift_id`(사용자 지정 코드)와 `id`(auto-increment) 이중 키 구조 — 레거시 호환 목적으로 추정
- Mid 근무(M)가 없으면 자동 생성하는 로직 존재 → 모든 그룹에 M 코드가 강제됨
- 그룹 간 코드 import 기능 존재 — 설정 표준화에 유용

## 2-2. 인력배치(ShiftManage) 설정

### 기능 설명
직종(RN, AN, 보조)별로 각 근무 슬롯에 필요한 인원 수를 설정한다.

### 이 기능이 필요한 이유
- "주간에 RN 5명, AN 2명 필요"와 같은 인력 요구사항이 근무표 생성의 핵심 입력
- 이 설정이 없으면 솔버가 각 근무에 몇 명을 배정할지 알 수 없다

### 코드 위치

| 구성 요소 | 경로 |
|-----------|------|
| Router | `app/routers/shifts.py:get_shift_manage, save_shift_manage` |
| DB Model | `app/db/models.py:ShiftManage` |
| Frontend | `ConfTab0` ManpowerInput |
| API 호출 | `src/api/req.ts` (`/shift-manage/RN`, `/shift-manage/save`) |

### API 상세

| Method | Endpoint | 권한 | 설명 |
|--------|----------|------|------|
| GET | `/shift-manage/{class_name}` | 인증됨 | 직종별 슬롯 설정 조회 |
| POST | `/shift-manage/save` | HN | 설정 저장 |

### DB 구조
복합 PK: `(office_id, group_id, nurse_class, shift_slot)`

| 컬럼 | 설명 | 예시 |
|------|------|------|
| `nurse_class` | 직종 | "RN", "AN", "보조" |
| `shift_slot` | 슬롯 번호 | 1(D), 2(E), 3(N), 5(M) |
| `main_code` | 주 근무코드 | "D" |
| `codes` | 허용 코드 배열 (JSON) | ["D", "D2"] |
| `manpower` | 필요 인원 | 5 |

### RosterConfig 연동
`roster_service.py:save_roster_config_service()`에서 ShiftManage의 manpower 합계를 `RosterConfig.day_req`, `eve_req`, `nig_req`에 자동 계산하여 저장:
```
day_req = SUM(manpower WHERE shift_slot=1)
eve_req = SUM(manpower WHERE shift_slot=2)
nig_req = SUM(manpower WHERE shift_slot=3)
```

### 연관 기능
- **2-1 근무코드**: 코드가 있어야 슬롯에 매핑 가능
- **2-3 일별 인력**: ShiftManage는 "기본값", DailyShift는 "날짜별 오버라이드"
- **2-8 RosterConfig**: day_req/eve_req/nig_req 자동 산출

### 현재 코드상 제약사항
- 슬롯 4가 필터링됨 (`shift_slot=4`는 주휴 슬롯으로 간주하여 save 시 제외)
- 직종 구분이 `nurse_class` 문자열에 의존 — Enum 미사용

## 2-3. 일별 인력(DailyShift) 설정

### 기능 설명
월의 각 날짜에 대해 D/E/N/M 필요 인원을 개별 설정한다. ShiftManage의 "기본값"을 날짜별로 오버라이드한다.

### 이 기능이 필요한 이유
- 공휴일, 주말, 특정 이벤트일에는 인력 요구가 다르다
- "평일에는 D 5명이지만, 일요일에는 D 3명" 같은 유연한 설정이 필요

### 코드 위치

| 구성 요소 | 경로 |
|-----------|------|
| Router | `app/routers/daily_shift.py` |
| Service | `app/services/daily_shift_service.py` |
| DB Model | `app/db/models.py:DailyShift` |
| Schemas | `app/schemas/daily_shift_schema.py` |
| Frontend | `ConfTab0` ConfSection_manpowerCalendar |

### API 상세

| Method | Endpoint | 권한 | 설명 |
|--------|----------|------|------|
| GET | `/daily-shift` | 인증됨 | 월별 일별 인력 조회 |
| PUT | `/daily-shift/monthly` | 인증됨 | 월 전체 일괄 설정 |
| PUT | `/daily-shift/daily` | 인증됨 | 날짜별 개별 설정 |
| GET | `/daily-shift/calendar` | 인증됨 | 캘린더 뷰 조회 |
| POST | `/daily-shift/save-calendar` | 인증됨 | 캘린더 데이터 저장 |

### 동작 원리
1. 월 초기화 시 ShiftManage의 manpower를 모든 날짜에 복사
2. `monthly` 업데이트: 모든 날짜에 동일 값 적용
3. `daily` 업데이트: 특정 날짜만 개별 변경
4. `is_month_closed()`: 마감된 월은 변경 불가

### 연관 기능
- **2-2 인력배치**: 초기값의 원천
- **3-4 근무표 생성**: 솔버가 일별 인력 데이터를 직접 참조

## 2-4. 법규 기반 제약 (Hard Constraints)

### 기능 설명
근로기준법 등 법적 의무 사항을 하드 제약으로 설정한다. 솔버가 이 제약을 **절대 위반하지 않는다**.

### 이 기능이 필요한 이유
- 법규 위반은 법적 책임을 수반하므로 시스템이 원천 차단해야 한다
- 간호사 안전과 환자 안전에 직결

### 코드 위치

| 구성 요소 | 경로 |
|-----------|------|
| Config 저장 | `app/routers/roster.py:save_roster_config` |
| Schema | `app/schemas/roster_schema.py:RosterConfigBase` |
| 솔버 적용 | `app/services/roster_system.py` (검증 메서드), `cp_sat_main_v3.py` |
| Frontend | `ConfTab0` ConfSection_law |

### 하드 제약 목록

| 설정 필드 | 기본값 | 설명 | 솔버 적용 |
|-----------|--------|------|-----------|
| `max_conseq_work` | 5 | 최대 연속 근무일 | `_check_max_consecutive_work_days()` |
| `three_seq_nig` | True | 3연속 야간 허용 | `_check_consecutive_night_limit()` |
| `max_nig_per_month` | 15 | 월 최대 야간 수 | `_check_monthly_night_limit()` |
| `banned_day_after_eve` | True | 이브닝 후 데이 금지 (E→D) | `_check_eve_before_day()` |
| N→D 금지 | 항상 적용 | 야간 후 데이 금지 | `_check_day_after_night()` |
| N→E 금지 | 항상 적용 | 야간 후 이브닝 금지 | `_check_night_before_evening()` |
| `two_offs_after_three_nig` | True | 3연속 야간 후 2일 오프 | `_check_two_offs_after_three_night()` |
| `two_offs_after_two_nig` | True | 2연속 야간 후 2일 오프 | `_check_two_offs_after_two_night()` |
| `not_one_night` | False | 단독 1야간 금지 (NONON 방지) | 솔버 변수 제약 |

### 적용 메커니즘
```
RosterConfig DB → NurseRosterConfig 데이터클래스 → RosterSystem 검증 메서드 → CP-SAT 하드 제약
```
- 하드 제약: 솔버가 **해를 찾을 수 없더라도** 위반하지 않음
- 위반 시: INFEASIBLE 발생 → 사용자에게 설정 검토 요청

### 연관 기능
- **2-5 내규**: 같은 RosterConfig 안에 공존. 법규가 내규보다 우선
- **3-5 근무표 편집**: 수동 편집 시에는 하드 제약 위반 가능 (경고만 표시)

## 2-5. 내규(병원 규칙) 설정 (Soft Constraints)

### 기능 설명
병원 자체 운영 규칙을 소프트 제약으로 설정한다. 가능한 한 지키되, 불가능하면 위반할 수 있다.

### 이 기능이 필요한 이유
- "주 2회 오프", "야간 균등 배분", "경력자 최소 배치" 같은 규칙은 법적 의무는 아니지만 운영 품질에 중요
- 하드 제약으로 하면 해가 없을 수 있으므로 소프트 제약으로 처리

### 소프트 제약 목록

| 설정 필드 | 기본값 | 설명 | 페널티 |
|-----------|--------|------|--------|
| `min_exp_per_shift` | 3 | 근무당 최소 경력자(년) | EXPERIENCE_SHORT_PENALTY |
| `req_exp_nurses` | 1 | 필요 경력 간호사 수 | 동일 |
| `two_offs_per_week` | True | 주 2회 오프 | WEEK_OFF_SHORT_PENALTY |
| `sequential_offs` | True | 오프 연속 배치 선호 | 목적함수 가중치 |
| `even_nights` | True | 야간 균등 배분 | NIGHT_DEVIATION_PENALTY (min-max) |
| `nod_noe` | True | N-O-D, N-O-E 패턴 최소화 | 목적함수 가중치 |
| `shift_priority` | 0.7 | 인력 충족 우선도 | 목적함수 비중 |
| `weekend_shift_ratio` | 0.0 | 주말 근무 비율 | 목적함수 가중치 |
| `off_days` | 가변 | 최소 오프일 수 | off_policy 제약 |
| `off_placement_mode` | 1 | 오프 배치 전략 (0/1/2) | 솔버 전략 변경 |

### 법규 vs 내규 구분

| 구분 | 위반 시 | 솔버 동작 | 설정 위치 |
|------|---------|-----------|-----------|
| **법규** (Hard) | INFEASIBLE | 절대 위반 불가 | ConfSection_law |
| **내규** (Soft) | 페널티 적용 | 다른 목표와 트레이드오프 | ConfSection_hospital |

### 현재 코드상 제약사항
- 법규와 내규가 **같은 테이블(RosterConfig)** 에 저장 — 구분이 컬럼 위치(프론트 탭)에만 의존
- 일부 설정(예: `off_days`)은 법규인지 내규인지 경계가 모호
- 프론트엔드의 ConfSection_law / ConfSection_hospital 분리가 유일한 구분 기준

## 2-6. 그레이드(역량등급) 설정

### 기능 설명
간호사를 역량 등급(1=상, 2=중, 3=하)으로 분류하고, 각 근무에 등급별 최소 배치 인원을 설정한다.

### 이 기능이 필요한 이유
- "주간 근무에 최소 1명의 1등급 간호사가 있어야 한다" 같은 역량 분포 요구사항
- 경험이 부족한 간호사만 배치되면 환자 안전 문제

### 코드 위치

| 구성 요소 | 경로 |
|-----------|------|
| Router | `app/routers/grade.py` |
| Service | `app/services/grade_service.py` |
| DB Model | `app/db/models.py:RosterGradeConfig` |
| 솔버 제약 | `app/services/constraints/grade_constraints.py` |
| 솔버 복구 | `app/services/repairs/grade_repair.py` |
| Frontend | `Head_nurse_management.tsx` GradeTable |
| API 호출 | `src/service/grade.ts` |

### API 상세

| Method | Endpoint | 권한 | 설명 |
|--------|----------|------|------|
| GET | `/grade/config` | HN | 그레이드 설정 조회 |
| POST | `/grade/config` | HN | 설정 저장/수정 |

### 설정 구조

```json
{
  "null_grade_policy": "LOWEST",    // 등급 미설정 간호사 처리: LOWEST/AVERAGE/RANDOM
  "use_dynamic_scaling": true,      // 인원 부족 시 비율 축소
  "constraints": {
    "D": {1: 1, 2: 2},             // 데이 근무: 1등급 1명, 2등급 2명 이상
    "E": {2: 1},                    // 이브닝: 2등급 1명 이상
    "N": {1: 1}                     // 야간: 1등급 1명 이상
  }
}
```

### NULL 등급 처리 정책

| 정책 | 동작 |
|------|------|
| `LOWEST` | 가장 낮은 등급(3)으로 취급 |
| `AVERAGE` | 전체 평균에 가장 가까운 등급으로 취급 |
| `RANDOM` | 간호사 ID 기반 결정론적 해시로 배분 |

### 솔버 적용 메커니즘
1. `grade_constraints.py`: 소프트 제약 (slack 변수 사용, penalty weight 160,000)
2. Dynamic scaling: 전체 인원 < 기준 인원일 때 비율 축소
3. `grade_repair.py`: 솔버 결과 후처리 — 등급 부족 시 간호사 교환으로 수리

### 연관 기능
- **1-4 간호사 관리**: `Nurse.grade` 필드에 등급 저장
- **2-8 RosterConfig**: `show_level` 플래그로 등급 표시 여부 제어

### 현재 코드상 제약사항
- 등급이 1~3 정수 — 확장(4등급, 5등급)은 가능하나 프론트엔드 대응 필요
- 소프트 제약이므로 인원이 부족하면 등급 요건이 충족되지 않을 수 있음
- `grade_repair`는 후처리로, 솔버 해보다 나은 배치를 찾지 못할 수도 있음

## 2-7. 주휴 설정

### 기능 설명
간호사별로 고정 주휴일을 배정한다. 순환 주기(월별/주별)를 설정하여 매월 요일이 변경되도록 할 수 있다.

### 이 기능이 필요한 이유
- 간호사가 매주 특정 요일에 쉴 수 있도록 보장
- "이번 달 월요일 → 다음 달 화요일" 순환으로 공평한 배분

### 코드 위치

| 구성 요소 | 경로 |
|-----------|------|
| Router | `app/routers/weekly_off.py` |
| Service | `app/services/weekly_off_service.py` |
| DB Model | `app/db/models.py:WeeklyOffSetting` (그룹 설정), `Nurse.weekly_off_*` (개인) |
| Schemas | `app/schemas/weekly_off_schema.py` |
| Frontend | `ConfTab3` WeeklyOffSettings, WeeklyOffTable |

### API 상세

| Method | Endpoint | 권한 | 설명 |
|--------|----------|------|------|
| GET | `/weekly-off/settings` | HN | 그룹 주휴 설정 조회 |
| PUT | `/weekly-off/settings` | HN | 그룹 설정 저장 |
| GET | `/weekly-off/nurses` | HN | 간호사별 주휴 조회 (미리보기 포함) |
| PUT | `/weekly-off/nurses` | HN | 간호사별 주휴 저장 |
| GET | `/weekly-off/my` | 인증됨 | 내 주휴 조회 |

### 설정 구조

**그룹 설정 (WeeklyOffSetting)**:

| 필드 | 설명 |
|------|------|
| `activate` | 주휴 기능 활성화 |
| `use_variable_cycle` | 순환 사용 여부 |
| `cycle_type` | "month" 또는 "week" |
| `shift_variation` | 월별 이동 폭 (기본 -1: 역방향 1칸) |
| `base_year/month` | 순환 기준 시점 |
| `cycle_start_date/interval` | 주 단위 순환 시 기준일/주기 |

**개인 설정 (Nurse)**:

| 필드 | 설명 |
|------|------|
| `weekly_off_enabled` | 이 간호사에게 주휴 적용 |
| `weekly_off_weekday` | 기준 요일 (0=월 ~ 6=일) |
| `is_weekend_off` | True면 주말만 오프 (주휴 별도 불필요) |

### 순환 계산 공식
```python
# 월별 순환
preview_weekday = (base_weekday + months_diff * shift_variation) % 7

# 주별 순환
weeks_diff = (target_date - cycle_start_date).days // (7 * cycle_interval)
preview_weekday = (base_weekday + weeks_diff * shift_variation) % 7
```

### 프리셉터 동기화
`update_nurses_weekly_off_service()`에서:
- 프리셉터의 주휴 변경 → 해당 프리셉터의 모든 프리셉티 주휴 자동 동기화
- 비선택적 강제 동기화 (프리셉티가 거부 불가)

### 연관 기능
- **1-8 프리셉터**: 주휴 동기화
- **2-8 RosterConfig**: `weekly_off_group` 플래그
- **3-4 근무표 생성**: 솔버가 주휴일을 오프로 고정 배치

### 현재 코드상 제약사항
- `is_weekend_off` 간호사는 주휴 계산 시 일요일이 기본 → 토요일은 별도 처리 없음
- 순환 설정 변경 시 기존 발행된 근무표에는 소급 적용되지 않음

## 2-8. 근무표 설정(RosterConfig) 버전 관리

### 기능 설명
위의 법규/내규/기타 설정을 하나의 설정 버전으로 묶어 저장한다. 근무표 생성 시 특정 버전을 선택하여 적용한다.

### 이 기능이 필요한 이유
- 설정 변경 이력을 추적할 수 있다
- "지난달 설정으로 다시 생성" 같은 운영이 가능
- 근무표와 설정의 1:1 매핑으로 감사 추적 가능

### 코드 위치

| 구성 요소 | 경로 |
|-----------|------|
| Router | `app/routers/roster.py` (config/save, config/versions, config/version/{ver}) |
| DB Model | `app/db/models.py:RosterConfig` (35+ 컬럼) |
| Schema | `app/schemas/roster_schema.py:RosterConfigCreate, RosterConfigBase` |
| Frontend | `ConfTab0` 저장 버튼, 버전 선택 |

### API 상세

| Method | Endpoint | 설명 |
|--------|----------|------|
| POST | `/roster/config/save` | 설정 저장 (새 버전 생성) |
| GET | `/roster/config/versions` | 버전 목록 조회 |
| GET | `/roster/config/version/{config_version}` | 특정 버전 상세 |

### 저장 시 부수 효과
`save_roster_config_service()` 실행 시:
1. ShiftManage에서 day_req/eve_req/nig_req 자동 계산
2. `use_mid=False`이면 간호사의 M 관련 설정 초기화
3. `weekly_off_group` 변경 시 WeeklyOffSetting 동기화

### 연관 기능
- **2-1~2-7의 모든 설정**: RosterConfig가 통합 저장소
- **3-4 근무표 생성**: `RosterRequest.config_id`로 버전 지정
- **Schedule.config_id**: 생성된 근무표에 사용된 설정 버전 기록

## 2-10. 프리셉터 연동 설정

### 기능 설명
프리셉터-프리셉티 동일 근무 배정의 강도와 방식을 설정한다.

### 설정 필드

| 필드 | 타입 | 설명 |
|------|------|------|
| `preceptor_gauge` | INT (0~10) | 동일 근무 배정 강도 (0=무시, 10=최대) |
| `preceptee_on` | BOOL | 프리셉티가 프리셉터 근무를 따라가는 모드 |
| `preceptee_shift_count` | BOOL | 프리셉티를 인력 충족 카운트에 포함 |

### 솔버 적용
- `preceptor_gauge > 0`: 소프트 제약으로 pair preference 적용
- `preceptee_on = True`: 프리셉티의 근무를 프리셉터와 동일하게 강제 (하드 제약에 가까움)
- `preceptee_shift_count = False`: 프리셉티를 인원에서 제외 → 실질적으로 "추가 인력"

### 연관 기능
- **1-8 프리셉터 관계**: `Nurse.preceptor_id` 설정 필요
- **2-7 주휴 설정**: 프리셉터 주휴 변경 시 프리셉티 동기화
