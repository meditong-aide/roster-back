# Layer 3: 운영 편의 및 예외 처리

> 이 문서는 매월 반복되는 운영 사이클과 일상적인 운영 보조 기능을 다룬다.  
> 변경 빈도가 높고(매월/매일), 실제 현장 사용자가 가장 자주 접하는 기능들이다.

---

## 월간 운영 사이클

```
[매월 반복]
1. Wanted 요청 오픈 (HN)           — 3-1
2. 간호사 선호 제출 (개인)          — 3-2
3. 마감 및 조정 (HN)               — 3-1, 3-3
4. 근무표 자동 생성 (HN)            — 3-4
5. 검토 및 수동 편집 (HN)           — 3-5
6. 발행 (HN)                       — 3-6
7. 간호사 확인 (개인)               — 3-7
8. 공유 (선택)                      — 3-8
```

---

## 3-1. Wanted (선호 수집 기간 관리)

### 기능 설명
월별 선호 요청 기간을 설정하고, 마감/연장/조기마감한다. AI(LangGraph)를 통한 자연어 분석도 포함.

### 이 기능이 필요한 이유
- 선호 수집 기간이 없으면 언제까지 요청을 받을지 기준이 없다
- 마감 후에는 추가 요청을 차단하여 근무표 생성의 안정성을 보장

### 코드 위치

| 구성 요소 | 경로 |
|-----------|------|
| Router | `app/routers/wanted.py` (20+ 엔드포인트) |
| Service | `app/services/wanted_service.py` |
| DB Model | `Wanted`, `WantedConfig`, `WantedRequest`, `NurseShiftRequest`, `NursePairRequest` |
| Frontend | `Roster_wanted.tsx`, `ConfTab4` |

### 핵심 API

| Method | Endpoint | 설명 |
|--------|----------|------|
| POST | `/wanted/request` | Wanted 기간 오픈 + 마감일 설정 |
| GET | `/wanted/status` | 현재 Wanted 상태 조회 |
| PATCH | `/wanted/close` | 조기 마감 |
| PATCH | `/wanted/deadline` | 마감일 변경 |
| POST | `/wanted/invoke` | AI 자연어 분석 호출 |
| POST | `/wanted/close-expired` | 만료된 Wanted 자동 마감 |

### 상태 흐름
```
(없음) → requested → closed
                  ↘ (exp_date 경과) → expired → closed
```

### WantedConfig (일별 제한)

| 필드 | 설명 |
|------|------|
| `max_requests` | 특정 날짜에 허용되는 최대 오프 요청 수 |
| `target_date` | 제한 대상 날짜 |
| `shift_type` | 제한 대상 근무 유형 |

### 초과 요청 관리
- `GET /wanted/over-limit-nurses`: 제한 초과 간호사 목록
- `POST /wanted/delete-excess-off/{nurse_id}`: 초과분 삭제

### 연관 기능
- **3-2 선호 제출**: Wanted가 open 상태일 때만 선호 제출 가능
- **3-3 조정판**: Wanted 결과를 HN이 확정
- **3-4 근무표 생성**: 확정된 선호가 솔버 입력

## 3-2. 선호 제출 (Preferences)

### 기능 설명
간호사가 특정 날짜에 원하는 근무(D/E/N) 또는 오프를 요청한다. 동료와의 근무 선호(같이/따로)도 설정 가능.

### 이 기능이 필요한 이유
- 간호사 개인 사정(학업, 가정, 건강 등)을 근무표에 반영
- 만족도 높은 근무표 = 이직률 감소, 근무 품질 향상

### 코드 위치

| 구성 요소 | 경로 |
|-----------|------|
| Router | `app/routers/preferences.py` |
| Service | `app/services/preferences_service.py` |
| DB Model | `ShiftPreference`, `WantedRequest`, `NurseShiftRequest`, `NursePairRequest` |
| Frontend | `Roster_wanted.tsx` 캘린더 UI |

### API 상세

| Method | Endpoint | 설명 |
|--------|----------|------|
| POST | `/preferences` | 임시 저장 (draft) |
| POST | `/preferences/submit` | 최종 제출 |
| POST | `/preferences/submit/empty` | 빈 선호 제출 |
| POST | `/preferences/retract` | 제출 철회 |
| GET | `/preferences/latest` | 최근 선호 조회 |
| GET | `/preferences/all` | 그룹 전체 선호 조회 (HN) |

### 데이터 구조

**선호 요청 3종**:

| 유형 | DB 테이블 | 설명 |
|------|-----------|------|
| 텍스트 요청 | `WantedRequest` | 자유 형식 텍스트 ("5일 오프 부탁드립니다") |
| 근무 선호 | `NurseShiftRequest` | 날짜별 근무 코드 + 가중치 (score 0~10) |
| 동료 선호 | `NursePairRequest` | work_together / work_apart + 가중치 |

### Pair Carry-Forward
- 이전 제출의 동료 선호가 새 제출에 자동 복사됨
- `_carry_forward_pair_data()`: 이전 request_id의 pair 데이터 → 새 request_id

### 연관 기능
- **3-1 Wanted**: open 상태여야 제출 가능
- **3-3 조정판**: 제출된 선호를 HN이 확정/수정
- **3-4 근무표 생성**: score 가중치로 솔버 목적함수 반영

## 3-3. 조정판 (FixedWanted)

### 기능 설명
수간호사가 간호사들의 선호 요청을 확인하고, 확정/수정/추가/비활성화한다. 확정된 항목은 솔버에 강력한 가중치(10점)로 반영된다.

### 이 기능이 필요한 이유
- 선호 충돌(같은 날 오프 요청이 인원 초과) 해결
- HN의 운영 판단 반영 (특정 간호사 우선, 팀 균형 고려)
- 확정 후 솔버에 "거의 하드 제약"으로 전달

### 코드 위치

| 구성 요소 | 경로 |
|-----------|------|
| Router | `app/routers/wanted.py` (adjustment 엔드포인트들) |
| Service | `app/services/wanted_service.py` |
| DB Model | `app/db/models.py:FixedWantedEntry` |
| Schemas | `FixedWantedCreate`, `AdjustmentResponse` |

### API 상세

| Method | Endpoint | 설명 |
|--------|----------|------|
| GET | `/wanted/adjustment/{year}/{month}` | 조정 데이터 조회 |
| POST | `/wanted/adjustment` | 확정 데이터 저장 |
| PATCH | `/wanted/adjustment/entry/{entry_id}/toggle` | 개별 항목 활성/비활성 토글 |
| POST | `/wanted/adjustment/{year}/{month}/reset` | 조정 초기화 |
| GET | `/wanted/fixed/{year}/{month}` | 확정 목록 조회 |

### FixedWantedEntry 구조

| 필드 | 설명 |
|------|------|
| `nurse_id` | 대상 간호사 |
| `shift_date` | 대상 날짜 |
| `shift_id` | 확정 근무 코드 |
| `is_applied` | 적용 여부 (토글 가능) |
| `source_type` | original / added / modified |
| `original_shift_id` | 수정 전 원래 코드 |
| `reason` | 사유 |
| `head_nurse_memo` | HN 메모/거절 사유 |

### 솔버 반영
- `RosterConfig.fixed_wanted_use_yn = True` 시 적용
- score = 10 (최대 가중치) → 솔버가 가능한 한 반드시 반영
- 하드 제약은 아니므로 인력 부족 시 위반 가능

### 연관 기능
- **3-2 선호 제출**: 원천 데이터
- **3-4 근무표 생성**: `use_fixed_wanted=True`로 호출 시 반영

## 3-4. 근무표 자동 생성

### 기능 설명
CP-SAT 최적화 엔진으로 월간 근무표를 자동 생성한다. 동기/비동기(SQS) 모드 지원.

### 이 기능이 필요한 이유
- 수십 명의 간호사, 수백 개의 제약을 수작업으로 만족시키는 것은 불가능
- 수학적 최적화로 법규 준수 + 선호 최대 반영 + 공정 배분

### 코드 위치

| 구성 요소 | 경로 |
|-----------|------|
| Router | `app/routers/roster_create.py` |
| Service | `app/services/roster_create_service.py` |
| 솔버 엔진 | `app/services/cp_sat_main_v3.py` (주력), `cp_sat_adaptive.py`, `cp_sat_main_v2.py` |
| 제약 모듈 | `app/services/constraints/grade_constraints.py` |
| 정책 모듈 | `app/services/cp_sat/off_policy.py`, `objective_terms.py`, `allowed_shift_types.py` |
| 후처리 | `app/services/repairs/grade_repair.py` |
| Frontend | `Roster_create.tsx` |

### API 상세

| Method | Endpoint | 설명 |
|--------|----------|------|
| POST | `/roster_create/generate` | 동기 생성 (응답 대기) |
| POST | `/roster_create/async` | 비동기 생성 (SQS → 워커) |
| POST | `/roster/request` | 스케줄 요청 |
| POST | `/roster_create/hold_generate` | 고정셀 포함 재생성 |

### 생성 요청 파라미터 (RosterRequest)

| 파라미터 | 설명 |
|----------|------|
| `year`, `month` | 대상 월 |
| `config_id` | 적용할 설정 버전 |
| `distribution_mode` | hybrid / balanced / preference / off |
| `grade_strategy` | BASE / TEAM / GRADE |
| `oversupply_balance_gauge` | 과잉 인력 분배 강도 (0~10) |
| `monthly_preference_gauge` | 월간 선호 반영 강도 (0~10) |
| `use_fixed_wanted` | FixedWanted 적용 여부 |
| `not_one_night` | 단독 1야간 금지 |

### 솔버 파이프라인
```
입력 수집 → 설정 로드 → 간호사/선호 데이터 수집
  → CP-SAT 모델 구성 (변수 + 하드 제약 + 소프트 제약 + 목적함수)
    → 솔버 실행 (시간 제한 있음)
      → 결과 매핑 (내부 인덱스 → DB shift_id)
        → 등급 후처리 (grade_repair)
          → 분석 저장 (RosterAnalytics)
            → Schedule/ScheduleEntry 저장
```

### 고정셀 재생성 (HoldGenerate)
- 사용자가 특정 셀을 수동으로 고정 → 나머지만 재생성
- `fixed_cells: [{nurse_id, date, shift_id}]`
- 고정된 셀은 솔버 변수에서 제외 (값 고정)

### 연관 기능
- **L2 전체**: 모든 규칙이 솔버 입력
- **3-1~3-3**: 선호 데이터가 솔버 입력
- **3-5 편집**: 결과를 수동 수정
- **3-10 대시보드**: 만족도 분석 데이터 생성

### 코드 위치

| 구성 요소 | 경로 |
|-----------|------|

- 빈 근무표 생성 → 수동 채우기

## 3-6. 근무표 발행

### 기능 설명
확정된 근무표를 간호사들에게 공식 공개한다. 발행 시 스냅샷이 생성되어 감사 추적 가능.

### 코드 위치

| 구성 요소 | 경로 |
|-----------|------|
| Router | `app/routers/roster.py:publish, unpublish` |
| DB Model | `IssuedRoster`, `IssuedRosterSnapshot` |

### API 상세

| Method | Endpoint | 설명 |
|--------|----------|------|
| POST | `/roster/publish` | 발행 (IssuedRoster + Snapshot 생성) |
| POST | `/roster/unpublish` | 발행 취소 (is_active=False) |
| GET | `/roster/issued` | 발행 목록 조회 |
| GET | `/roster/issued_roster` | 발행 상세 조회 |

### 발행 시 동작
1. `IssuedRoster` 레코드 생성 (version 자동 증가)
2. `IssuedRosterSnapshot` 생성 — 전체 상태 JSON 저장:
   - `meta_json`: 인원 수, 제약 요약
   - `config_json`: 사용된 RosterConfig 스냅샷
   - `nurses_json`: 간호사 목록 스냅샷
   - `shifts_json`: 근무코드 스냅샷
   - `shift_manage_json`: 인력배치 스냅샷
   - `roster_json`: 전체 배정 데이터
   - `violations_json`: 위반 사항 목록

### 연관 기능
- **3-7 보기**: 발행된 근무표만 일반 간호사에게 표시
- **3-8 공유**: 발행 후 외부 공유 가능
