## 2. 엔티티 분류: 구조 / 정책 / 권한

### 구조 (Structure) 엔티티
> "무엇이 존재하는가?" — 조직, 인력, 근무유형의 정의

```
Office ──┬── Group ──┬── Team
         │           ├── Nurse (소속)
         │           └── Shift (근무코드)
         └── (병원 전체)
```

**특징**: 변경 빈도 낮음, 다른 모든 엔티티의 FK 참조 대상

### 정책 (Policy) 엔티티
> "어떤 규칙을 적용하는가?" — 제약, 설정, 임계값

```
RosterConfig ──── 법규 하드 제약 + 내규 소프트 제약 + 기타 설정
RosterGradeConfig ── 등급 분포 제약
WeeklyOffSetting ── 주휴 순환 정책
ShiftManage ──── 인력 배치 기준
DailyShift ──── 날짜별 인력 오버라이드
WantedConfig ──── 선호 제한 정책
```

**특징**: 그룹 단위 스코프, 솔버가 직접 참조

### 권한 (Role/Permission) 엔티티
> "누가 무엇을 할 수 있는가?"

```
Permission (마스터 목록)
  └── UserPermission (간호사-권한 매핑)
       └── UserPermissionScope (그룹 스코프)

PermissionAuditLog (변경 감사)
```

**특징**: DB 모델 완성, 실제 적용 미완성 (is_head_nurse/is_master_admin 플래그에 의존)

### 운영 (Operation) 엔티티
> "실제로 무슨 일이 일어나는가?" — 월간 사이클의 데이터

```
Wanted → ShiftPreference/WantedRequest/NurseShiftRequest/NursePairRequest
  → FixedWantedEntry
    → Schedule → ScheduleEntry
      → IssuedRoster → IssuedRosterSnapshot
        → ShareLink
```

### 분석/감사 (Analytics/Audit) 엔티티
> "결과가 어떠했는가?"

```
RosterAnalytics ── 만족도 지표
RosterRequestDetails ── 요청별 반영 상세
DeletedNurseHistory ── 인력 삭제 이력
PermissionAuditLog ── 권한 변경 이력
IssuedRosterSnapshot ── 발행 시점 전체 스냅샷
```

## 5. 네이밍 혼란 및 개선안

### 5-1. 혼란스러운 네이밍

| 현재 이름 | 혼란 요소 | 실제 의미 | 개선안 |
|-----------|-----------|-----------|--------|
| `is_night_nurse` | Boolean처럼 보이지만 JSON 배열 (0,1,2,3 코드) | 허용 근무 유형 프로필 코드 | `shift_profile` 또는 `allowed_shift_codes` |
| `level_` | 뒤에 `_`가 붙음 (Python 예약어 회피) | 간호사 직급/레벨 | `job_level` (Python 예약어와 충돌 없음) |
| `Wanted` | "원한다"는 모호함 | 선호 수집 기간/요청 | `PreferencePeriod` 또는 `PreferenceWindow` |
| `WantedRequest` | Wanted + Request 이중 의미 | 자유형식 선호 텍스트 | `PreferenceTextRequest` |
| `NurseShiftRequest` | "Request"가 HTTP Request와 혼동 | 근무 선호 항목 | `ShiftPreferenceEntry` |
| `ShiftPreference` | NurseShiftRequest와 역할 겹침 | 선호 제출 상태 관리 | `PreferenceSubmission` |
| `FixedWantedEntry` | "Wanted"의 확장이 아닌 별개 개념 | HN이 확정한 근무 배정 | `ConfirmedAssignment` |
| `shift_gb` | 약어 의미 불명 | 근무 분류/그룹 (추정) | `shift_category` |
| `hn_id` | JSON 필드지만 단수형 | HN nurse_id 배열 | `admin_nurse_ids` |
| `mb_part` | 약어 의미 불명 | 부서 코드 (mworks 연동) | `department_code` |
| `EmpAuthGbn` | 한글 약어 혼합 | 직원 권한 구분 (ADM/HDN) | `auth_level` |
| `gw_useYN`, `qpis_useYN` | 레거시 시스템 약어 | 외부 시스템 사용 여부 | 유지 (레거시 호환) |

### 5-2. 테이블/모델 수준 개선안

| 현재 | 문제 | 제안 |
|------|------|------|
| `Nurse` (35+ 컬럼) | 인사정보 + 근무속성 + 기능토글이 한 테이블 | 분리 고려: `Nurse`(인사) + `NurseProfile`(근무속성) + `NurseSettings`(기능토글) |
| `RosterConfig` (35+ 컬럼) | 법규 + 내규 + UI설정 + 팀 + 프리셉터가 한 테이블 | 분리 고려: `RegulationPolicy`(법규) + `OperationalPolicy`(내규) + `RosterDisplayConfig`(UI) |
| `Shift.shift_id` + `Shift.id` 이중 키 | PK가 2개 (사용자 코드 + auto-increment) | `id`를 PK로 통일, `shift_code`를 UNIQUE로 변경 |

> **주의**: 위 제안은 현재 코드를 대규모 변경해야 하므로, 단기적으로는 네이밍 주석/문서화로 혼란을 줄이는 것이 현실적.

## 6. 선호 관련 엔티티 관계 정리

선호 시스템이 가장 복잡한 영역이므로 별도 정리:

```
[선호 수집 사이클]

Wanted (그룹×월 단위 기간)
  │
  ├── WantedConfig (일별 제한 설정)
  │
  └── [간호사별 제출]
       │
       ├── ShiftPreference (제출 상태 관리: draft/submitted)
       │
       ├── WantedRequest (자유형식 텍스트)
       │    └── request_id로 버전 관리
       │
       ├── NurseShiftRequest (날짜별 근무 선호)
       │    └── (nurse_id, request_id, detailed_request_id, shift_date)
       │
       └── NursePairRequest (동료 선호)
            └── (nurse_id, request_id, month, detailed_request_id, target_id)

[확정 과정]

FixedWantedEntry (HN 확정)
  └── source_type: original / added / modified
  └── is_applied: 활성/비활성 토글

[솔버 참조]

CP-SAT ← FixedWantedEntry (use_fixed_wanted=True 시)
       ← NurseShiftRequest + NursePairRequest (일반 선호)
```

### 문제점
- `ShiftPreference`와 `WantedRequest`/`NurseShiftRequest`가 같은 선호를 다른 형태로 저장
- `ShiftPreference.data`는 JSON (전체 선호), `NurseShiftRequest`는 정규화된 행
- 두 경로가 공존하여 어떤 것이 최종 데이터인지 코드를 따라가야 알 수 있음

## 7. 솔버와 엔티티 매핑

| 솔버 입력 | 원천 엔티티 | 변환 위치 |
|-----------|------------|-----------|
| 간호사 목록/속성 | `Nurse` | `cp_sat_main_v3.py:create_nurses_from_db()` |
| 근무 요구량 | `ShiftManage` + `DailyShift` | `roster_create_service.py` |
| 하드 제약 | `RosterConfig` | `cp_sat_main_v3.py:create_config_from_db()` |
| 소프트 제약 | `RosterConfig` | 동일 |
| 등급 제약 | `RosterGradeConfig` | `grade_constraints.py:add_grade_constraints()` |
| 오프 정책 | `RosterConfig.off_days` + 주휴 | `off_policy.py:resolve_effective_off_days()` |
| 근무 선호 | `NurseShiftRequest` 또는 `FixedWantedEntry` | `roster_create_service.py:_collect_nurses_and_preferences()` |
| 동료 선호 | `NursePairRequest` | 동일 |
| 이전 달 이월 | `ScheduleEntry` (전월) | `roster_service.py:get_prev_month_tail_service()` |
| 주휴 날짜 | `Nurse.weekly_off_*` + `WeeklyOffSetting` | `wanted_service.py:_compute_weekly_off_days()` |
