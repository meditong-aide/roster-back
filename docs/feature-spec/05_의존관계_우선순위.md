# 기능 간 의존관계 / 적용 순서 / 우선순위

> 설정 기능들이 실제로는 서로 영향을 주는 구조를 정리한다.

---

## 1. 설정 적용 우선순위 (높음 → 낮음)

```
┌─────────────────────────────────────────────────────────┐
│ Level 0: 시스템 하드코딩 제약                            │
│   N→D 금지, N→E 금지 (코드에 직접 구현, 설정 불가)       │
├─────────────────────────────────────────────────────────┤
│ Level 1: 법규 하드 제약 (RosterConfig)                   │
│   max_conseq_work, max_nig_per_month, three_seq_nig     │
│   two_offs_after_three_nig, two_offs_after_two_nig      │
│   banned_day_after_eve, not_one_night                   │
│   → 절대 위반 불가. 위반 시 INFEASIBLE.                  │
├─────────────────────────────────────────────────────────┤
│ Level 2: 인력 배치 요구 (ShiftManage + DailyShift)       │
│   day_req, eve_req, nig_req + 날짜별 오버라이드          │
│   → 가능한 한 충족. shift_priority 가중치로 강도 조절    │
├─────────────────────────────────────────────────────────┤
│ Level 3: 내규 소프트 제약 (RosterConfig)                  │
│   min_exp_per_shift, two_offs_per_week, even_nights     │
│   sequential_offs, nod_noe                               │
│   → 페널티 기반. 다른 목표와 트레이드오프                │
├─────────────────────────────────────────────────────────┤
│ Level 4: 등급 분포 제약 (RosterGradeConfig)               │
│   근무별 등급 최소 인원                                   │
│   → 소프트 제약 (slack 변수). penalty weight 160,000     │
├─────────────────────────────────────────────────────────┤
│ Level 5: 그룹/팀 정책                                     │
│   team_balance (gauge 0~10), weekly_off (고정 오프)       │
│   preceptor_gauge (동일 근무 강도)                        │
│   → 소프트 제약. gauge 값으로 강도 조절                  │
├─────────────────────────────────────────────────────────┤
│ Level 6: 확정 선호 (FixedWantedEntry)                     │
│   HN이 확정한 개인별 근무/오프                            │
│   → 소프트 제약이지만 score=10 (매우 강력)               │
├─────────────────────────────────────────────────────────┤
│ Level 7: 개인 선호 (NurseShiftRequest, NursePairRequest) │
│   간호사 본인이 제출한 선호                               │
│   → 소프트 제약. score 0~10 (가변)                       │
└─────────────────────────────────────────────────────────┘
```

### 우선순위 해석

| 상황 | 결과 |
|------|------|
| 법규 vs 인력배치 | 법규가 이기면 인력 미달 허용 (안전 우선) |
| 인력배치 vs 내규 | shift_priority 가중치로 밸런스 |
| 등급 vs 선호 | 등급 penalty(160K) >> 선호 score(1~10) |
| 확정선호 vs 개인선호 | 확정(10) > 개인(가변) — 같은 소프트 제약이지만 가중치 차이 |
| 법규 vs 확정선호 | 법규가 항상 우선 — 확정선호가 위반 시 무시됨 |

## 2. 설정 순서 의존관계

### 필수 선행 관계 (선행 → 후행)

```
Office 등록
  └── 1-1. 그룹 생성
       ├── 1-2. HN 지정
       │    └── (HN이 있어야 아래 모든 HN 전용 기능 사용 가능)
       ├── 1-4. 간호사 등록
       │    ├── 1-3. 팀 배정
       │    ├── 1-8. 프리셉터 관계 설정
       │    ├── 2-6. 그레이드 배정 (Nurse.grade)
       │    └── 2-7. 주휴 배정 (Nurse.weekly_off_*)
       ├── 2-1. 근무코드 설정
       │    └── 2-2. 인력배치 설정 (코드가 있어야 슬롯 매핑)
       │         └── 2-3. 일별 인력 설정 (기본값이 있어야 오버라이드)
       └── 2-4~2-5. 법규/내규 설정
            └── 2-8. RosterConfig 저장
                 └── 3-1. Wanted 오픈
                      └── 3-2. 선호 제출
                           └── 3-3. 조정판 확정
                                └── 3-4. 근무표 생성
                                     └── 3-5. 편집
                                          └── 3-6. 발행
                                               └── 3-7. 보기
```

### 의존관계 표

| 후행 기능 | 선행 기능 | 관계 유형 |
|-----------|-----------|-----------|
| 그룹 관리자(1-2) | 그룹(1-1) + 간호사(1-4) | 필수 |
| 팀 배정(1-3) | 그룹(1-1) + 간호사(1-4) | 필수 |
| 프리셉터(1-8) | 양쪽 간호사(1-4) | 필수 |
| 인력배치(2-2) | 근무코드(2-1) | 필수 |
| 일별 인력(2-3) | 인력배치(2-2) | 필수 (초기값 원천) |
| 그레이드 제약(2-6) | 간호사 grade 설정(1-4) | 권장 |
| 주휴(2-7) | 간호사(1-4) | 필수 |
| RosterConfig(2-8) | 인력배치(2-2) | 필수 (day_req 자동 계산) |
| 팀 밸런스(2-9) | 팀(1-3) | 권장 |
| 선호 제출(3-2) | Wanted 오픈(3-1) | 필수 |
| 조정판(3-3) | 선호 수집(3-2) | 권장 |
| 근무표 생성(3-4) | RosterConfig(2-8) | 필수 |
| 발행(3-6) | 근무표 존재(3-4/3-5) | 필수 |
| 만족도(3-10) | 근무표 생성(3-4) | 필수 (생성 시 자동 저장) |

## 3. 충돌 가능 항목

### 3-1. 인력 vs 제약 충돌

| 충돌 상황 | 원인 | 결과 | 해결 방법 |
|-----------|------|------|-----------|
| 인원 부족 + 최대 연속근무 5일 | 간호사 수 < 필요 인원 × 7/5 | INFEASIBLE | 인원 추가 또는 제약 완화 |
| 야간 인원 부족 + 월 최대 야간 15회 | 야간 가능 간호사 수 < nig_req × 30/15 | INFEASIBLE | 야간 가능 인력 추가 |
| 등급 1 인원 부족 + 매 근무 1명 필수 | grade=1 간호사 < D+E+N 슬롯 | 소프트 위반 | dynamic_scaling 활성 또는 제약 축소 |

### 3-2. 설정 간 논리적 충돌

| 충돌 A | 충돌 B | 영향 |
|--------|--------|------|
| `banned_day_after_eve=True` | 소수 인원으로 E→D 전환 필요 | INFEASIBLE |
| `two_offs_after_three_nig=True` | `max_nig_per_month` 낮게 설정 | 이중 제약으로 야간 배정 극히 제한 |
| `preceptee_on=True` | 프리셉터가 야간 전용 | 프리셉티도 야간만 배정 |
| `team_balance_gauge=10` | 팀 인원 불균형 | 소수 팀에 과중 근무 |
| `fixed_wanted` 과다 고정 | 인력배치 요구 | 고정 때문에 인력 배치 불가 |
| `weekly_off` 같은 요일 집중 | 해당 요일 인력 부족 | 해당 요일 인력 미달 |

### 3-3. 프리셉터-주휴 연쇄 충돌

```
프리셉터 A의 주휴 = 월요일
  └─ 프리셉티 B의 주휴 = 자동으로 월요일 (동기화)
     └─ 그런데 월요일에 이미 3명 주휴 배정
        └─ 해당 요일 인력 부족 가능
```

**현재 코드의 처리**: 동기화는 강제이며, 인력 부족은 솔버가 소프트하게 해결 시도.

## 4. Override / 상속 / 기본값 구조

### 4-1. 설정의 계층적 적용

| 설정 | Scope | Override 가능? | 상속? | 기본값? |
|------|-------|---------------|-------|---------|
| **RosterConfig** | 그룹 | 버전별로 새로 저장 (덮어쓰기 아님) | X | 코드 내 하드코딩 기본값 |
| **ShiftManage** | 그룹 × 직종 × 슬롯 | 직접 수정 | X | 없음 (초기 설정 필수) |
| **DailyShift** | 그룹 × 날짜 | ShiftManage 기본값을 날짜별 override | O (ShiftManage → DailyShift) | ShiftManage의 manpower |
| **GradeConfig** | 그룹 | 직접 수정 (1 row per group) | X | null_grade_policy="LOWEST" |
| **WeeklyOffSetting** | 그룹 | 직접 수정 | X | activate=False |
| **Nurse 속성** | 개인 | 개별 수정 | X | 각 필드별 기본값 |
| **FixedWantedEntry** | 개인 × 날짜 | 개인 선호를 override | O (개인선호 → 확정선호) | 없음 |

### 4-2. 그룹 간 공유/복사

| 대상 | 기능 | 코드 위치 |
|------|------|-----------|
| **근무코드** | 다른 그룹에서 가져오기 (import) | `shifts.py:available-imports, import-to-group` |
| **RosterConfig** | 없음 (그룹별 독립) | — |
| **GradeConfig** | 없음 (그룹별 독립) | — |
| **WeeklyOff** | 없음 (그룹별 독립) | — |
| **근무표** | 복사 (같은 그룹 내) | `roster.py:copy/{source_schedule_id}` |

### 4-3. 현재 코드상 명확도 판정

| 항목 | 명확도 | 설명 |
|------|--------|------|
| 법규 vs 내규 구분 | **암묵적** | 같은 RosterConfig 테이블, 프론트엔드 탭으로만 구분 |
| DailyShift → ShiftManage 기본값 | **명시적** | `get_or_init_month()`에서 명확히 복사 |
| FixedWanted → 선호 override | **명시적** | score=10, source_type 기록 |
| 솔버 가중치 우선순위 | **코드 내 하드코딩** | penalty weight가 코드에 상수로 정의 |
| 프리셉터-주휴 동기화 | **암묵적** | 문서화 없이 코드에서 자동 수행 |
| RBAC → 실제 권한 검사 | **단절** | DB 모델은 있지만 권한 검사 로직과 연결 안됨 |

## 5. 월간 운영 사이클 타임라인

```
[D-21]  HN: 2-2, 2-3 인력배치/일별인력 확인 및 조정
[D-20]  HN: 2-4~2-5 법규/내규 설정 검토 (변경 시)
[D-20]  HN: 2-8 RosterConfig 저장 (변경 시)
[D-18]  HN: 3-1 Wanted 오픈 (마감일 설정)
[D-18 ~ D-7]  간호사: 3-2 선호 제출
[D-7]   자동: 3-1 Wanted 마감 (exp_date 도달)
[D-6]   HN: 3-3 조정판에서 선호 확정/조정
[D-5]   HN: 3-4 근무표 자동 생성
[D-4]   HN: 3-5 결과 검토, 수동 편집
[D-3]   HN: 3-10 만족도 확인, 필요 시 재생성
[D-2]   HN: 3-6 발행
[D-1]   간호사: 3-7 근무표 확인
[D-0]   해당 월 시작
```

**D = 해당 월 첫 날**

## 6. INFEASIBLE 발생 주요 원인과 진단 가이드

| 원인 카테고리 | 구체적 원인 | 진단 방법 |
|--------------|-------------|-----------|
| **인력 부족** | 간호사 수 < (day_req + eve_req + nig_req) × 30 / (30 - off_days) | 인원 대비 인력배치 총합 비교 |
| **야간 제약 과다** | 야간 가능 인원 × max_nig_per_month < nig_req × 30 | is_night_nurse 프로필별 야간 총량 계산 |
| **연속근무 제약** | max_conseq_work 대비 인원 회전 불가 | off_days + weekly_off가 충분한지 확인 |
| **고정셀 과다** | fixed_cells가 인력배치와 충돌 | 고정셀 날짜별 인력 합산 vs 요구량 비교 |
| **주휴 집중** | 같은 요일에 주휴 과다 → 해당일 인력 부족 | 요일별 주휴 인원 분포 확인 |
| **E→D 금지 + 소수 인원** | D/E 교대 불가 + 인원 부족 | banned_day_after_eve 해제 시 해결되는지 테스트 |
