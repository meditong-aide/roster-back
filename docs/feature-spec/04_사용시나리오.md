# 기능별 사용 시나리오

> 각 기능을 **누가, 언제, 왜** 사용하는지, 잘못 설정하면 어떤 문제가 발생하는지를 정리한다.

---

## Layer 1: 조직/권한/구조

### 1-1. 그룹(병동) 관리

| 항목 | 내용 |
|------|------|
| **누가** | 마스터 관리자(ADM) |
| **언제** | 병원 최초 설정, 새 병동 신설, 조직 개편 시 |
| **해결 문제** | 병동별 독립적인 근무표 운영 단위 생성 |
| **잘못 설정 시** | 간호사가 잘못된 병동에 소속 → 근무표에 잘못 배치. 그룹 없으면 모든 기능 사용 불가 |
| **선행 확인** | Office(병원) 등록 완료 |
| **함께 확인** | 1-2(관리자 지정), 1-4(간호사 배정) |

### 1-2. 그룹 관리자(HN) 지정

| 항목 | 내용 |
|------|------|
| **누가** | 마스터 관리자(ADM) |
| **언제** | 신규 수간호사 부임, 인사이동, 교대 관리자 변경 시 |
| **해결 문제** | 누가 이 병동의 근무표를 만들고 관리할 수 있는지 결정 |
| **잘못 설정 시** | HN 미지정 → 설정/생성/발행 불가. 잘못된 사람 지정 → 권한 남용 가능 |
| **선행 확인** | 1-1(그룹 존재), 1-4(해당 간호사 등록) |
| **함께 확인** | 1-7(인증) — 지정 후 재로그인 필요 |

### 1-3. 팀 관리

| 항목 | 내용 |
|------|------|
| **누가** | 수간호사(HN) |
| **언제** | 병동 내 팀 구성 변경 시 (반기~연 1회). 팀 밸런스 사용 시 필수 |
| **해결 문제** | 대규모 병동에서 팀 단위 인력 관리 및 근무 균형 분배 |
| **잘못 설정 시** | 팀 밸런스 활성화 상태에서 팀 미구성 → 밸런스 무의미. 잘못된 멤버 배정 → 불균형 |
| **선행 확인** | 1-1(그룹), 1-4(간호사) |
| **함께 확인** | 2-9(팀 밸런스 설정) |

### 1-4. 간호사 인력 관리

| 항목 | 내용 |
|------|------|
| **누가** | 수간호사(HN), 마스터 관리자(ADM) |
| **언제** | 신규 입사, 퇴사, 인사이동, 속성 변경 시 (수시) |
| **해결 문제** | 근무표 대상 인력의 등록과 속성 관리 |
| **잘못 설정 시** | - `experience` 오류 → 경력자 배치 제약 미작동 |
|                  | - `grade` 미설정 → null_grade_policy 적용 (의도와 다를 수 있음) |
|                  | - `is_night_nurse` 오류 → 야간 배정 불가/과잉 |
|                  | - `active=0`인데 모르고 넘김 → 근무표에서 누락 |
| **선행 확인** | 1-1(그룹 존재) |
| **함께 확인** | 1-3(팀), 1-8(프리셉터), 2-6(그레이드), 2-7(주휴) |

### 1-8. 프리셉터 관계

|------|------|

| **선행 확인** | 1-4(양쪽 간호사 등록) |
| **함께 확인** | 2-7(주휴 동기화), 2-10(프리셉터 연동 설정) |

## Layer 2: 근무표 생성 규칙

### 2-1. 근무코드(Shift) 설정

| 항목 | 내용 |
|------|------|
| **누가** | 수간호사(HN) |
| **언제** | 최초 설정 시, 근무 체계 변경 시 (예: 2교대→3교대) |
| **해결 문제** | 병동에서 사용하는 근무 유형 정의 |
| **잘못 설정 시** | - `auto_schedule=0` 실수 → 솔버가 해당 코드 무시, 인력 부족 |
|                  | - `type` 오류 (근무↔휴무 혼동) → 오프/근무 카운트 오류 |
|                  | - 시간(start/end) 미설정 → duration 계산 불가 |
| **선행 확인** | 1-1(그룹) |
| **함께 확인** | 2-2(인력배치), 3-2(선호 — show_in_preference) |

### 2-2. 인력배치(ShiftManage)

| 항목 | 내용 |
|------|------|
| **누가** | 수간호사(HN) |
| **언제** | 인력 증감 시, 근무코드 추가/삭제 후, 시즌별 조정 |
| **해결 문제** | 각 근무에 몇 명이 필요한지 정의 |
| **잘못 설정 시** | - 인원 과다 설정 → INFEASIBLE (해 없음) |
|                  | - 인원 과소 설정 → 실제 필요 인력 미달 |
|                  | - 직종(class) 오류 → RN/AN 배정 오류 |
| **선행 확인** | 2-1(근무코드 존재) |
| **함께 확인** | 2-3(일별 인력), 2-8(RosterConfig 자동 계산) |

### 2-7. 주휴 설정

| 항목 | 내용 |
|------|------|
| **누가** | 수간호사(HN) |

| **선행 확인** | 1-4(간호사), 2-1(주휴용 근무코드 존재) |

## Layer 3: 운영 편의 및 예외 처리

### 3-1. Wanted (선호 수집 기간)

| 항목 | 내용 |
|------|------|
| **누가** | 수간호사(HN) — 기간 설정. 간호사 — 상태 확인 |
| **언제** | 매월 근무표 생성 2~3주 전 |
| **해결 문제** | 선호 수집의 시작/종료를 명확하게 관리 |
| **잘못 설정 시** | - 마감일 없이 오픈 → 무한 수집, 생성 시점 불분명 |
|                  | - 마감일 너무 촉박 → 간호사들이 선호 미제출 → 만족도 저하 |
|                  | - WantedConfig 제한 미설정 → 특정 날짜에 오프 요청 쏠림 |
| **선행 확인** | 없음 (독립적으로 오픈 가능) |
| **함께 확인** | 3-2(선호 제출), 3-3(조정판) |

### 3-2. 선호 제출

| 항목 | 내용 |
|------|------|
| **누가** | 일반 간호사 |
| **언제** | Wanted 오픈 ~ 마감 사이 |
| **해결 문제** | 개인 사정을 근무표에 반영받기 위함 |
| **잘못 설정 시** | - 과도한 오프 요청 → 모두 반영 불가, 만족도 측정 왜곡 |
|                  | - 미제출 → 0점 선호로 처리, 솔버가 자유롭게 배치 |
| **선행 확인** | 3-1(Wanted open 상태) |
| **함께 확인** | 3-3(HN 조정) |

### 3-3. 조정판 (FixedWanted)

| 항목 | 내용 |
|------|------|
| **누가** | 수간호사(HN) |
| **언제** | 선호 마감 후, 근무표 생성 전 |
| **해결 문제** | 선호 충돌 해결, 운영 판단 반영, 확정 사항 강제 |
| **잘못 설정 시** | - 너무 많은 항목을 고정 → 솔버 자유도 감소 → INFEASIBLE 위험 |
|                  | - 고정 항목이 법규와 충돌 → 고정 항목이 무시되거나 해 없음 |
| **선행 확인** | 3-1(마감), 3-2(선호 수집 완료) |
| **함께 확인** | 3-4(생성 시 use_fixed_wanted=True 필요) |

### 3-4. 근무표 자동 생성

| 항목 | 내용 |
|------|------|
| **누가** | 수간호사(HN) |
| **언제** | 매월 1회 (선호 마감 후) |
| **해결 문제** | 수십 명 × 30일 × 다수 제약을 만족하는 최적 근무표 자동 산출 |
| **잘못 설정 시** | - INFEASIBLE: 제약 과다 또는 인력 부족 |
|                  | - 낮은 만족도: 내규 가중치 미조정 |
|                  | - 긴 생성 시간: 인원 과다 또는 제약 복잡도 |
| **선행 확인** | L2 전체 설정, 3-1~3-3(선호 수집/확정) |
| **함께 확인** | 3-5(편집), 3-10(만족도 확인) |
