# Layer 1: 조직/권한/구조 관리

> 이 문서는 "누가 어디에 속하고, 무엇을 할 수 있는지"를 정의하는 기능들을 다룬다.  
> 변경 빈도가 낮고(분기~연 1회), 나머지 모든 기능의 전제 조건이 된다.

---

## 1-1. 그룹(병동) 관리

### 기능 설명
병원 내 간호 단위(병동/부서)를 그룹으로 생성·관리한다. 모든 데이터(간호사, 근무표, 설정)는 그룹 단위로 격리된다.

### 이 기능이 필요한 이유
- 병원은 여러 병동으로 구성되며, 각 병동마다 독립적인 근무표가 필요하다.
- 그룹이 없으면 간호사 소속, 근무표 범위, 설정 범위를 특정할 수 없다.

### 코드 위치

| 구성 요소 | 경로 |
|-----------|------|
| Router | `app/routers/groups.py` |
| DB Model | `app/db/models.py:Group` |
| Frontend | `src/components/Nav.tsx` (GroupList, AddGroupModal) |
| API 호출 | `src/api/req.ts` (`/groups`) |

### API 상세

| Method | Endpoint | 권한 | 설명 |
|--------|----------|------|------|
| GET | `/groups` | ADM | 전체 그룹 목록 |
| POST | `/groups` | ADM | 그룹 생성 (`{group_name}`) |
| PATCH | `/groups/{group_id}` | ADM | 그룹명 변경 |
| GET | `/groups/by-office` | ADM/HN | hn_id 포함 그룹 목록 |
| GET | `/groups/my-admin-groups` | 인증됨 | 내가 관리하는 그룹 목록 |

### 주요 입력값/출력값

- **입력**: `group_name` (VARCHAR 50)
- **출력**: `{group_id, group_name, office_id}`
- **DB 컬럼**: `group_id`(PK), `office_id`(FK→offices), `group_name`, `hn_id`(JSON, 관리자 nurse_id 배열)

### 연관 기능
- **1-2 그룹 관리자 지정**: 생성된 그룹에 HN을 배정해야 운영 가능
- **1-3 팀 관리**: 그룹 하위에 팀 구성
- **1-4 간호사 관리**: 간호사를 그룹에 소속시킴
- **모든 L2/L3 기능**: group_id를 기준으로 동작

### 현재 코드상 제약사항
- 그룹 삭제 API가 없음 — 하위 데이터(간호사, 근무표 등)가 있으면 삭제 불가하므로 의도적 미구현으로 추정
- `hn_id`가 JSON 배열로 저장됨 — FK 제약이 없어 존재하지 않는 nurse_id가 들어갈 수 있음

## 1-2. 그룹 관리자(HN) 지정

### 기능 설명
특정 간호사를 그룹 관리자(수간호사)로 지정하거나 해제한다. 한 간호사가 여러 그룹을 관리할 수 있다.

### 이 기능이 필요한 이유
- 수간호사만 근무표 설정/생성/발행이 가능하다.
- 관리자가 없는 그룹은 설정 변경이나 근무표 생성이 불가능하다.

### 코드 위치

| 구성 요소 | 경로 |
|-----------|------|
| Router | `app/routers/groups.py:update_hn_admin` |
| DB Model | `Group.hn_id` (JSON), `Nurse.hn_auth`, `Nurse.is_head_nurse` |
| Frontend | `Nav.tsx` 그룹 관리 드롭다운 |

### API 상세

| Method | Endpoint | 권한 | 설명 |
|--------|----------|------|------|
| PUT | `/groups/hn-admin` | ADM | 그룹 관리자 지정/해제 |

### 주요 입력값/출력값

- **입력**: `{nurse_id, group_ids[]}` — 해당 간호사에게 관리 권한을 줄 그룹 목록
- **동작**: 
  - `Group.hn_id` JSON 배열에 nurse_id 추가/제거
  - `Nurse.hn_auth = 'HN'` 또는 `None` 설정
  - `Nurse.is_head_nurse = True/False` 설정

### 연관 기능
- **1-1 그룹 관리**: 그룹이 먼저 존재해야 함
- **1-4 간호사 관리**: 간호사가 먼저 등록되어 있어야 함
- **인증(auth.py)**: JWT에 `is_head_nurse`, `hn_auth` 포함 → 로그인 시점의 권한 반영

### 현재 코드상 제약사항
- HN 지정 후 해당 간호사가 재로그인해야 JWT에 권한이 반영됨
- `Group.hn_id`는 JSON 배열이므로 동시 수정 시 race condition 가능성 있음
- ADM만 가능하며, HN이 다른 HN을 지정하는 것은 불가

## 1-3. 팀 관리

### 기능 설명
그룹 내에서 하위 팀을 생성하고, 간호사를 팀에 배정한다. 팀은 근무표 생성 시 팀 밸런스 제약에 사용된다.

### 이 기능이 필요한 이유
- 대규모 병동에서는 팀 단위로 인력을 관리하는 경우가 많다.
- 팀 밸런스 설정(L2-9)을 사용하려면 팀이 먼저 구성되어 있어야 한다.

### 코드 위치

| 구성 요소 | 경로 |
|-----------|------|
| Router | `app/routers/teams.py` |
| Service | `app/services/team_service.py` |
| DB Model | `app/db/models.py:Team` (composite PK: office_id, group_id, team_id) |
| Frontend | `Head_nurse_management.tsx` TeamSettingContents, TeamTableRows |
| API 호출 | `src/api/teams.ts` |

### API 상세

| Method | Endpoint | 권한 | 설명 |
|--------|----------|------|------|
| GET | `/teams` | 인증됨 | 팀 목록 + 소속 간호사 |
| PUT | `/teams` | 인증됨 | 팀 일괄 동기화 (생성/이름변경/멤버추가·삭제/팀삭제) |

### 주요 입력값/출력값

- **입력 (PUT)**: `TeamBulkOpsRequest`
  ```json
  {
    "teams": [
      {"team_id": null, "team_name": "A팀", "add": ["nurse_1"], "remove": []},
      {"team_id": 1, "team_name": null, "add": ["nurse_2"], "remove": ["nurse_3"]}
    ],
    "delete_team_ids": [3]
  }
  ```
- **출력**: `List[TeamWithMembers]` — `{team_id, team_name, team_members[]}`

### 연관 기능
- **1-4 간호사 관리**: 간호사가 등록되어 있어야 팀에 배정 가능
- **2-9 팀 밸런스**: `RosterConfig.team_balance_enable`이 True일 때 팀 구성이 근무표 생성에 반영
- **2-7 주휴 설정**: `weekly_off_service`에서 팀 이름이 표시됨

### 현재 코드상 제약사항
- `team_id`는 그룹 내에서 auto-increment (max+1) — 삭제 후 재사용되지 않음
- 팀 삭제 시 소속 간호사의 `team_id`가 NULL로 초기화됨 (하드 삭제)
- Unique 제약: 같은 그룹 내 같은 팀명 불가 (`ux_teams_group_name`)

## 1-4. 간호사 인력 관리

### 기능 설명
간호사 등록·수정·삭제·순서 관리. 근무표 시스템의 가장 기본적인 데이터 단위.

### 이 기능이 필요한 이유
- 간호사가 등록되지 않으면 어떤 기능도 동작하지 않는다.
- 경력, 역할, 등급, 야간 가능 여부 등의 속성이 근무표 생성 품질에 직결된다.

### 코드 위치

| 구성 요소 | 경로 |
|-----------|------|
| Router | `app/routers/nurses.py` (25+ 엔드포인트) |
| Service | `app/services/nurse_service.py`, `app/services/excel_service.py` |
| DB Model | `app/db/models.py:Nurse` (35+ 컬럼) |
| Schemas | `app/schemas/roster_schema.py:NurseProfile, NurseProfileUpdate` |
| Frontend | `Head_nurse_management.tsx` NurseManagementTables, SortableNurseRow |
| API 호출 | `src/api/nurses.ts`, `src/hooks/useNurses.ts` |

### 핵심 속성 분류

| 분류 | 속성 | 근무표 생성 영향 |
|------|------|-----------------|
| **기본정보** | name, account_id, emp_num, birth_date, gender, phone, email | 없음 (표시용) |
| **근무속성** | experience, role, level_, grade, is_night_nurse, fixed_shift, work_shifts | **직접 반영** — 솔버가 참조 |
| **조직속성** | group_id, team_id, sequence, active | 소속 및 표시 순서 |
| **주휴속성** | weekly_off_enabled, weekly_off_weekday, is_weekend_off | 주휴 배정에 반영 |
| **관계속성** | preceptor_id, is_head_nurse, hn_auth | 프리셉터 동기화, 권한 |
| **개인조정** | personal_off_adjustment, wanted_max_requests | 개인별 오프/요청 수 조절 |
| **기능토글** | enable_nurse_pair_preference, enable_aide | 개인별 기능 ON/OFF |

### 주요 API (25개 중 핵심)

| Method | Endpoint | 설명 |
|--------|----------|------|
| GET | `/nurses` | 그룹 내 간호사 목록 |
| PATCH | `/nurses/{nurse_id}` | 개별 수정 |
| POST | `/nurses/bulk-update` | 일괄 수정 |
| POST | `/nurses/sequence/save` | 순서 저장 |
| POST | `/nurses/add-to-group` | 그룹에 추가 |
| DELETE | `/nurses/{nurse_id}` | 삭제 (ADM) |
| POST | `/nurses/upload2-validate` → `/upload2-confirm` | 엑셀 2단계 업로드 |

### 연관 기능
- **모든 L2 기능**: 간호사 속성(experience, grade, is_night_nurse 등)이 규칙의 대상
- **모든 L3 기능**: 선호 제출, 근무표 배정, 분석의 주체

### 현재 코드상 제약사항
- `Nurse` 모델에 35+개 컬럼 → 책임이 과도하게 집중 (인사정보 + 근무속성 + 기능토글이 한 테이블)
- 삭제 시 `DeletedNurseHistory`에 스냅샷 저장 (감사 추적)
- `is_night_nurse`가 JSON 배열 (0~3 정수값) — 네이밍이 직관적이지 않음 (실제로는 "허용 근무 유형 코드")

## 1-6. RBAC 권한 관리

### 기능 설명
리소스(NURSE, ROSTER, PREFERENCE 등) × 액션(READ, CREATE, UPDATE, DELETE) 조합으로 세분화된 권한을 간호사에게 부여한다. 그룹 단위 스코프 적용 가능.

### 이 기능이 필요한 이유
- 현재 HN/ADM 2단계 권한만으로는 세밀한 접근 제어가 어렵다.
- 향후 "특정 그룹의 근무표만 조회 가능한 관리자" 같은 역할이 필요할 수 있다.

### 코드 위치

| 구성 요소 | 경로 |
|-----------|------|
| DB Models | `app/db/models.py:Permission, UserPermission, UserPermissionScope, PermissionAuditLog` |
| Frontend | **(미구현 추정)** — 프론트엔드에서 RBAC 관련 API 호출이 확인되지 않음 |

### 현재 상태
- DB 테이블은 완성됨 (Permission, UserPermission, UserPermissionScope, PermissionAuditLog)
- **라우터/서비스가 없음** — DB 모델만 존재하고, 이를 CRUD하는 API가 확인되지 않음
- 실제 권한 검사는 여전히 `is_head_nurse` / `is_master_admin` 플래그에 의존
- **추정**: 향후 확장을 위해 준비된 구조

### 엔티티 구조
```
Permission (code, resource, action)
  └── UserPermission (nurse_id, permission_id, scope_type: ALL|GROUPS)
       └── UserPermissionScope (group_id) -- scope_type=GROUPS일 때
```

## 1-7. 인증/로그인

### 기능 설명
JWT 쿠키 기반 인증. MSSQL 레거시 시스템의 로그인 검증과 연동.

### 코드 위치

| 구성 요소 | 경로 |
|-----------|------|
| Router | `app/routers/auth.py`, `app/routers/token.py` |
| Frontend | `src/api/auth.ts`, `TokenLogin.tsx` |

### 인증 흐름
```
[일반 로그인]
POST /auth/login (username, password)
  → MSSQL Member.login_check()
  → JWT 생성 → httpOnly Cookie "access_token" 설정
  → UserSchema 반환

[SSO 토큰 로그인]
POST /token/ (clientId, clientSecret) → 토큰 발급
POST /token/login (token, MemberID) → JWT Cookie 설정
```

### 권한 체계

| 레벨 | 식별 방법 | 접근 범위 |
|------|-----------|-----------|
| 일반 간호사 | 인증된 사용자 | 본인 데이터, 본인 그룹 근무표 |
| 수간호사(HN) | `is_head_nurse=True`, `hn_auth='HN'` | 관리하는 그룹의 설정/생성/발행 |
| 마스터 관리자(ADM) | `is_master_admin=True`, `EmpAuthGbn='ADM'` | 전체 그룹 관리, 그룹/HN 관리 |

### 연관 기능
- **1-2 그룹 관리자**: HN 지정이 JWT 토큰에 반영
- **그룹 전환**: HN은 `POST /auth/switch-group`으로 관리하는 다른 그룹으로 전환 가능

## 1-8. 프리셉터(멘토-멘티) 관계

### 기능 설명
경력 간호사(프리셉터)와 신규 간호사(프리셉티) 간의 멘토링 관계를 설정한다.

### 이 기능이 필요한 이유
- 신규 간호사는 경력자와 같은 근무에 배정되어야 현장 교육이 가능하다.
- `RosterConfig.preceptor_gauge`로 동일 근무 배정 강도를 조절한다.

### 코드 위치

| 구성 요소 | 경로 |
|-----------|------|
| DB Field | `Nurse.preceptor_id` (FK → nurses.nurse_id, 자기참조) |
| Config | `RosterConfig.preceptor_gauge` (0~10), `preceptee_on`, `preceptee_shift_count` |
| Weekly Off | `weekly_off_service.py` — 프리셉터 주휴 변경 시 프리셉티 자동 동기화 |
| Frontend | `Head_nurse_management.tsx` 프리셉터 관계 관리 |

### 솔버 연동
- `preceptee_on=True`: 프리셉티가 프리셉터의 근무를 따라감
- `preceptee_shift_count=True`: 프리셉티를 인력 충족 카운트에 포함
- `preceptor_gauge` (0~10): 동일 근무 배정 소프트 제약 강도

### 연관 기능
- **2-7 주휴 설정**: 프리셉터 주휴 변경 → 프리셉티 자동 동기화
- **2-10 프리셉터 연동 설정**: RosterConfig에서 강도 조절
- **3-4 근무표 생성**: CP-SAT 솔버가 pair preference로 반영
