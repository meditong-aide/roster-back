# 프리셉티 스케줄링 — 솔버 1급 시민화 (Option C)

작성 2026-07-02. 대상 파일: `app/services/cp_sat/fallback_lex.py` (SKIP_PRIMARY=1 실경로).

## 1. 배경과 문제

프리셉티(preceptee)는 프리셉터(preceptor)의 시프트를 그대로 인계(팔로우)받는다. 기존 구현은
팔로우를 **하드 등가**(`preceptee[d] == preceptor[d]`)로 걸되, 프리셉티를 **모든 하드제약
(연속근무·전환 ND/ED/NE·나이트연속·나이트후OFF·1N 등)에서 제외**했다. "프리셉터가 합법이면
따라가는 프리셉티도 합법"이라는 전제였다.

이 전제는 **프리셉티가 특정일에 근무코드를 확정(fixed_wanted)** 하는 순간 깨진다. 그 fixed일은
팔로우하지 않는데 **인접일은 계속 프리셉터를 복사**하므로, [복사된 인접일] + [fixed일] 조합이
어떤 제약 검증도 받지 않는다.

> 예: 프리셉터 19일 N, 프리셉티 20일 fixed D → 프리셉티는 19일(팔로우)=N, 20일=D → **ND 위반**이 통과.

## 2. 설계 (Option C: 프리셉티를 솔버 1급 시민으로)

프리셉티에게 **하드제약을 native로 부여**하고 팔로우를 하드 등가로 유지한다. fixed일 인접에서 생기는
불법이 프리셉티 자신의 제약으로 잡히고, 하드 등가를 통해 그 제약이 **프리셉터에게 되전파**된다
(양방향 조율). 해결 불가하면 완화하지 않고 infeasible로 보고한다.

핵심 통찰: 등가가 이미 `preceptee==preceptor`라 **순수 팔로우일에는 제약이 redundant**하다.
실제 동작 변화는 **① 프리셉티 fixed일 ② 월경계**에서만 발생한다.

## 3. 동작 상세

### 3.1 팔로우 (하드 등가)
non-fixed 팔로우일: `preceptee[d] == preceptor[d]` (전 시프트 등가).

### 3.2 프리셉티 fixed일
등가에서 **제외**하고 프리셉티 본인 fixed 코드를 하드 고정한다 → **프리셉티 fixed > 팔로우**.

### 3.3 프리셉터 특수코드(휴가/공가/W 등)
프리셉터가 비표준 fixed 코드인 날은 등가 대신 프리셉티를 **OFF**로 둔다(특수코드를 복사하지 않음).

### 3.4 같은 날 프리셉터/프리셉티가 다른 fixed
프리셉터=A, 프리셉티=B (A≠B) → 등가가 스킵되므로 **각자 자기 fixed를 지킨다**(프리셉티=B, 프리셉터=A).
**infeasible 아님.**

### 3.5 프리셉티 fixed ↔ 인접 전파 (양방향)
프리셉티 fixed일이 인접일과 불법패턴을 만들면, 인접일(팔로우=프리셉터 복사)의 프리셉터가 조정된다.

> 예 (ND): 프리셉티 20일 fixed D + 19일 팔로우.
> - ND 하드: `¬(프리셉티19=N ∧ 프리셉티20=D)`. 20=D 고정 → 프리셉티19≠N → 등가 → **프리셉터19≠N 강제**.
> - 솔버는 프리셉터 나이트를 19–20 대신 **20–21로 페어링**. 프리셉티 19=(N아님)·20=D → 합법.
> - 21일도 불가하면 → **infeasible 보고**.

즉 충돌 판정 기준은 "프리셉터 vs 프리셉티 같은 날"이 아니라 **"프리셉티 fixed vs 프리셉티 인접일 패턴"**이다.

## 4. 적용 / 비적용 제약

**적용(프리셉티도 하드):** 전환 ND/ED/NE · 연속근무 ≤5(6연 배제) · 나이트연속 ≤3 · 나이트3후OFF2 ·
나이트2후OFF2 · 1N 금지(단 **프리셉티 fixed셀은 제외** = 고정 단독N 존중) · N-O-D/E(나이트 후 1오프 근무).
월 나이트 상한 ≤15는 기존부터 전 간호사 적용.

**비적용(프리셉티 계속 제외):** 4연속OFF · 주말오프 · 월경계 OFF창 · N전담 · soft/objective. (정책 외이거나,
fixed OFF 스트레치를 오infeasible 시킬 위험이라 의도적 제외.)

## 5. 실행 경로

`fallback_lex.py`만 수정(SKIP_PRIMARY=1 실경로). primary(`cp_sat_basic._build_full_model`)는 **미변경**
— 미사용 경로이며, 마스터 게이트 제거 시 allowed_shifts 등이 등가와 충돌해 infeasible 위험. SKIP_PRIMARY를
뒤집을 경우 primary도 동일 처리 필요.

## 6. 검증

프리셉티 보유 3병동(중환자실1·중환자실2·9B) × 7·8월 = **6건 전부 생성·커버부족 0·팔로우 정상·정책 하드락 위반 0**
(2회 반복, 비결정성 배제). OLD(적용 전) 대비 중1 7월 `consecutive_work·not_one_night·rec_3n2o·rec_2n2o`
4건 → 0. 정규 간호사는 해당 제약이 원래 하드라 위반 불가 → 그 위반들은 프리셉티 것이었음이 입증됨.

## 7. 코드 위치 (근사)

- 팔로우 등가 + fixed일 제외 + 특수코드 OFF: 팔로우 루프 (`preceptee_follow` 블록, ~L1198–1223).
- 프리셉티 fixed 프리솔브 하드고정: 같은 블록 말미 (~L1224–1235).
- 8종 제약 `_is_preceptee_at(n): continue` 해제: 전환(~L1514)·1N(~L1616, fixed셀 제외 가드 추가)·
  ban-night-before-off·연속근무(~L1731)·나이트연속(~L1766)·N3→2OFF·N2→2OFF·N-O-D/E.

## 8. 미결 / 주의

- **월경계**: 프리셉티 own prev-month tail이 프리셉터와 달라 경계에서 infeasible 늘 수 있음(하드 방침상 정상).
- 프리셉티 fixed가 자체로 정책위반(6연/4N 등)이면 infeasible 보고(의도).
- 전환 ND 면제(사용자가 N→D 양쪽을 명시 고정하면 허용)는 프리셉티 fixed가 `fixed` dict에 없어 프리셉티엔
  적용되지 않음 → 프리셉티는 ND를 명시고정으로도 못 뚫음(더 엄격, 안전 측). 필요 시 별도 결정.
