# 신규 병원 온보딩 마법사 — 기획

> 작성 2026-08-26. 목적: "n월 셋팅"을 버튼 하나로 끝까지 안내하는 흐름 설계.
> 범위: 근무자 세팅 → 근무코드 → 과거 근무표 → 생성 셋팅(팀·그레이드·개인속성).

---

## 0. 결론 먼저 — 스킬이 아니라 **별도 세션**이다

에이전트 스킬 하나로 만들면 안 된다. 근거는 취향이 아니라 구조다.

1. **스킬은 1턴 완결이다.** `run_skill(db, params) → dict`. 온보딩은 5~6단계에 걸쳐
   상태가 누적되고 중간 이탈·재개가 있다. 스킬 시그니처에 담기지 않는다.
2. **되묻기 왕복이 지금 죽어 있다.** `pending_clarify` 는 저장·복원되지 않고
   `ChatRequest` 에 `clarify_answers` 필드가 없어 `_resume_clarify` 가 **프로덕션에서
   실행될 수 없다**(2026-08-26 실측). 온보딩은 되묻기의 연속이라 이 위에 못 올린다.
3. **단계마다 승인 강도가 다르다.** 근무자 선택은 사람 확정 필수, 근무코드는 추론+수정,
   근무표 저장은 되돌리기 어려움. 하나의 preview→confirm 규약으로 안 덮인다.
4. **부분 성공이 정상이다.** 근무자까지만 하고 내일 이어서 — 가 실제 사용 패턴이다.
   스킬은 전부-아니면-전무라 이걸 표현 못 한다.

**→ 온보딩 세션(백엔드 상태 기계) + 전용 화면(모달/페이지). 에이전트는 진입과 보조.**

## 1. 단계 정의와 기존 자산

각 단계에서 **새로 만들 것과 이미 있는 것**을 갈랐다. 이미 있는 걸 다시 만들면
규칙이 두 벌이 된다(오늘 나이트 일괄에서 서비스를 재사용한 것과 같은 원칙).

| 단계 | 하는 일 | 기존 자산 | 신규 |
|---|---|---|---|
| **S1 근무자** | 병동 명단 편성 | `GET /nurses/available-members` → `POST /nurses/add-to-group` (**HN 가능**) | 후보 제시 UX·동명이인 확인 |
| **S2 근무코드** | 코드 등록 | `POST /shifts/upload-validate` → `upload-confirm`, `shifts/add`, **`available-imports`→`import-to-group`**(다른 병동 코드 복제) | **엑셀 격자 → 코드 추론** |
| **S3 과거 근무표** | n-1월 표 확보 | `POST /roster/save`(셀 저장), `create-empty`, `copy` | **엑셀 격자 → 셀 파싱** |
| **S4 팀** | 팀 편성 | `manage_teams` 스킬 · 팀 API | 일괄 배정 UX |
| **S5 그레이드** | 등급 부여 | `manage_grade` · `update_person_attr` | 일괄 UX |
| **S6 개인 속성** | 근무유형·N개수 | `update_person_attr`(allowed_shifts) · **`update_monthly_limit` scope=전체**(오늘 추가) | 표 형태 일괄 편집 |

**S2 의 숨은 지름길**: `available-imports` → `import-to-group` 이 이미 있다. 같은 office
다른 병동에 코드가 이미 있으면 **추론 없이 복제**하면 된다. 신규 병원의 두 번째 병동부터는
이 경로가 정답이고, 추론은 **첫 병동에만** 필요하다. 이걸 먼저 제안해야 한다.

## 2. 근무코드 추론 (S2) — 가능하다. 단 이름이 아니라 **분포**로 판단한다

추론 대상은 자유 텍스트가 아니라 열거형이라 범위가 좁다:
`shift_gb`(데이/이브닝/나이트/오프/휴가) · `default_shift`(D/E/N/O/M) · `type`(근무/오프) ·
`start_time`/`end_time` · `allday` · `is_weekly_off`.

**이름 매칭은 보조 신호일 뿐이다.** "HD 가 Day 인가"는 격자가 답한다:

| 증거 | 판별 |
|---|---|
| 나이트 다음날 그 코드가 안 나옴 | 그 코드는 주간 계열 |
| OFF 와 같은 날 동시 등장 안 함 | 근무 코드(type=근무) |
| 하루 등장 인원이 D 와 비슷 | D 계열 |
| 특정 요일에만 등장 | 주휴/고정 계열 |
| 연속 2~3일 뒤 반드시 OFF 2일 | 나이트 계열 |

### PoC 실측 (2026-08-26) — `tests/agent_qa/shift_infer_poc.py`

실 DB(dev, 137만 셀) 25개 병동 · 각 최신 근무표 1개. 정답은 `shifts.default_shift` 가
채워진 코드(**1643개 중 481개, 29% 만 채워져 있다** — 문제의 전제가 실측으로 확인됨).

| 판정 대상 107건 | v1 | v2 | v5(최종) |
|---|---|---|---|
| 맞음 | 23.5% | 70.6% | **36.4%** |
| **틀림** | 0% | 9.8% | **0.9%** (1건) |
| 보류 | 76.5% | 19.6% | 62.6% |
| 판정한 것 중 정확도 | 100% | 87.8% | **97.5%** |

라벨별: `O` 18/0 · `D` 16/0 · `N` 5/0 · `E` 0/1

**무엇을 배웠나 — 세 번 틀리면서 얻은 것**

1. **"N 다음날 OFF" 는 안 통한다.** N 은 연속으로 붙어 다음날이 또 N 이다
   (실측 N→N 56% / N→O 41%). v1 이 N 을 한 건도 못 잡은 이유.
2. **진짜 지문은 전이 비대칭이다.** `banned_day_after_eve`(이브닝 다음날 데이 금지)가
   하드 제약이라 격자에 **E→D 0% / D→E 33%** 로 찍힌다. 이 비대칭이 근무 순서
   `D→E→N` 을 복원해 준다. 이름을 전혀 안 보고도 된다.
3. **동점인데 억지로 세우면 조용히 틀린다.** v2 의 오답 9.8% 는 **전부** 전이 점수가
   `+0`(순서 근거 없음)인데 상위 3개를 D/E/N 에 배정한 것이었다.
4. **앵커(OFF) 실패는 연쇄한다.** OFF 를 argmax 로만 고르면 근무 코드가 뽑히는 병동이
   있고(D 가 일평균 29% 로 최대), 그러면 근무 순서까지 역전돼 오답이 3배로 늘었다.
   → 2위와의 **마진**을 요구하고, 마진이 없으면 그 병동 전체를 보류한다.

**남은 오답 1건**: 간호사 5명 병동의 E→N 오판. 소규모라 전이 관측이 희박하다
(`MIN_OBS=8` 게이트로도 안 걸림). 병동 규모 게이트를 더 올리면 잡히나 커버리지가 준다.

**판정**: 쓸 수 있다. 단 **커버리지 36%** 이므로 "자동으로 다 채워준다"가 아니라
**"확실한 것만 채우고 나머지는 비워서 준다"** 로 UX 를 잡아야 한다. `O`·`D` 는 신뢰도가
높고(34/34), `E` 는 사실상 못 맞힌다 — **E/D 구분은 시간 정보가 있어야 한다.**

**핵심 설계 = 정확도가 아니라 abstain.** 틀리면 **조용히** 틀린다 — `HD` 를 Day 로 잘못
넣어도 근무표는 만들어지고 커버리지만 어긋난다. 그래서:

- 각 코드에 **확신도와 근거**를 함께 낸다("나이트 다음날 미등장 12회 → 주간 계열").
- 확신이 낮으면 **비워서 사람에게 넘긴다.** 추측으로 채우지 않는다.
- 화면에서 **그 자리에서 수정 후 저장**. 저장 전까지 DB 반영 없음.

## 3. 상태 모델

```
OnboardingSession
  id, group_id, year, month, created_by, status(draft|done|abandoned)
  step            : S1..S6 중 현재
  step_state_json : 단계별 누적 결과(선택된 nurse_id 목록, 추론된 코드 초안, 파싱 격자…)
  decisions_json  : 사람이 확정한 판단(동명이인 선택, 코드 수정 이력)  ← 감사용
```

**왜 서버 상태인가** — 엑셀 파싱 결과·추론 초안은 크고, 중간 이탈·재개가 정상이며,
"무엇을 사람이 확정했는지"가 나중에 분쟁 소지가 된다(동명이인 오선택). 프론트 메모리에
두면 새로고침에 날아가고 감사도 안 된다.

**단계 커밋 단위** — 각 단계는 **자기 단계만 커밋**하고 다음으로 넘어간다. 전체를 한
트랜잭션으로 묶지 않는다(S1 까지 하고 내일 이어서가 정상이므로).

## 4. ★ 방어 지점 — 여기가 기획의 본체

### D1. 동명이인
`available-members` 는 후보 구분에 필요한 재료를 **이미 다 내려준다** — 사번
(`OfficeEmpNum`)·생년월일·입사일(`joindate`)·부서 4계층·직위·경력.

- **이름만으로 자동 확정 금지.** 동명이 2명 이상이면 반드시 사람이 고른다.
- 카드에 사번·입사일·부서를 **항상** 함께 표시(동명이 아니어도).
- 선택 결과를 `decisions_json` 에 남긴다 — 나중에 "누가 이 사람을 골랐나"가 필요하다.

### D2. mWorks 오등록
우리가 고칠 수 없다(그룹웨어가 원본이고 수정은 ADM 영역). 온보딩은:
- 이상 징후를 **표시만** 한다(입사일 없음/미래, 직위 공란, 부서 미매칭).
- **진행은 막지 않는다** — 막으면 온보딩이 멈추고 사용자는 우회로를 찾는다.
- 대신 `decisions_json` 에 "이상 상태로 진행함"을 기록한다.

### D3. 이미 다른 병동 소속인 사람
`available-members` 는 **office 전체에서 이미 등록된 사람을 제외**한다. 그래서 "우리
병동 사람인데 목록에 없다"가 반드시 발생한다.
- `registered_map` 이 `{group_id, group_name}` 을 갖고 있으므로
  **"이미 ○○병동 소속 — 병동이동으로 처리"** 로 안내하고 `manage_assignment` 경로로 보낸다.
- 이걸 안 하면 사용자는 "왜 없지" 로 멈춘다.

### D4. 추론 오류 (S2)
§2 참조. **abstain 우선.** 확신 없는 코드는 비워서 넘긴다.

### D5. 발행된 근무표
S3 에서 과거 표를 넣거나 S1 에서 명단을 바꿀 때, 그 달이 이미 발행됐으면 충돌한다.
- 병동이동은 오늘 서비스단 가드를 넣었다(`_assert_no_active_issued_roster`).
- **S3 근무표 저장에도 같은 가드가 필요하다** — 아직 없다.

### D6. 과거 소속 재현 불가 — ★ **고치지 않기로 결정(2026-08-26)**
`nurses.group_id` 는 **시점 없는 단일 값**이다. 온보딩의 본질이 "과거 몇 달치를 넣는 것"
인데, 8월엔 A·9월엔 B였던 사람의 8월 표를 재생성하면 **B 로 나온다.** 과거가 현재로 덮인다.

**결정: 소속 시점화는 하지 않는다. 과거 소속은 바꿀 수 없는 것으로 확정한다.**

따라서 온보딩은 이 제약을 **전제로** 설계한다:
- 과거 월 근무표는 **저장·조회용**이다. 그 달을 **재생성하면 현재 소속 기준으로 어긋난다.**
- S3 화면에 그 경고를 상시 노출하고, 과거 월 재생성 진입 자체를 막는 것을 검토한다.
- 병동이동 이력(`NurseAssignment`)은 원장이므로 **append 로만** 쌓는다. UPDATE·DELETE
  금지 — 원장마저 덮으면 시점 복원 수단이 하나도 안 남는다.
  (되돌아오는 이동 = 반대 방향 create. 입력 실수 무르기 = cancel. 스킬 설명에 명시함.)

### D7. 부분 실패·재개
단계별 커밋 + 세션 상태로 해결. 각 단계 진입 시 **현재 DB 상태를 다시 읽어** 표시한다
(세션에 캐시한 값을 믿지 않는다 — 그사이 다른 사람이 바꿨을 수 있다).

## 5. 자연어를 어디서 받는가

**단계 안의 조작은 화면이 받고, 자연어는 두 지점에만 붙인다.**

1. **진입** — "9월 셋팅 하고 싶어" / "새 병동 세팅" → 에이전트가 `navigate(onboarding)`
   + 세션 생성. 대상 월·병동을 발화에서 뽑아 프리필.
2. **단계 내 질문** — "이 사람 왜 목록에 없어?" / "HD가 뭐야?" 같은 **조회성** 질문.
   화면 옆 위젯이 답한다. **조작은 안 한다.**

**조작을 자연어로 받지 않는 이유**: 온보딩은 선택지가 격자·표 형태라 클릭이 압도적으로
빠르고 정확하다. "3번째 김민지 골라줘"를 자연어로 받으면 D1(동명이인) 방어가 무너진다.
