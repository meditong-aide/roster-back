# 월초 1N 제약 스킵 변경 기록

## 문서 목적
- `Fix: 월초 1N 제약 스킵 추가` 커밋의 수정 배경과 변경 내용을 정리한다.
- 월경계에서 발생한 hard 제약 충돌을 왜/어떻게 해소했는지 공유한다.

---

## 1) 왜 수정이 필요했는가
- 운영 규칙상 `not_one_night=true`(1N 금지)일 때, 단발성 N은 금지된다.
- 하지만 월경계에서는 전월 마지막 패턴 때문에 익월 day0에 N이 강제되는 케이스가 존재한다.
- 이때 day0에 일반 1N 금지 제약까지 그대로 적용하면, 해가 존재해도 모델이 hard fail로 떨어질 수 있다.

---

## 2) 무엇을 수정했는가

### 2.1 월경계 보정 정보 생성
- 전월 tail 분석에서 `day0 N 고정`이 필요한 간호사를 식별한다.
- 해당 간호사는 익월 day0에 N을 강제하고, 필요한 recovery OFF를 함께 적용한다.

### 2.2 1N 제약의 day0 예외 처리
- `not_one_night=true`라도,
  - **day0이 월경계 보정으로 N 고정된 경우에 한해** day0 단발 N 금지 체크를 스킵한다.
- day1 이후 일반 구간은 기존 1N 금지 규칙을 그대로 유지한다.

### 2.3 메인/폴백 일관성
- 메인 CP-SAT 경로와 fallback 경로 모두 동일한 예외 규칙을 적용해 경로별 동작 차이를 줄였다.

### 2.4 DB 변경 사항
- 본 커밋 범위에서는 **신규 DB 컬럼/테이블 변경 없음**.
- 기존 데이터(전월 스케줄, wanted/fixed 셀)를 해석하는 로직만 보정했다.

#### 점검 SQL (스키마 변경 없음 확인)
```sql
-- 변경 커밋과 직접 연결된 신규 컬럼이 없는지 확인 (예시)
SELECT COLUMN_NAME
FROM INFORMATION_SCHEMA.COLUMNS
WHERE TABLE_SCHEMA = 'dbo'
  AND TABLE_NAME IN ('roster_config', 'daily_shift')
  AND COLUMN_NAME IN ('use_mid', 'm_count');
```

---

## 3) 기대 효과
- 월경계 강제 N + 1N 금지 충돌로 인한 불필요한 infeasible 감소
- 전월 패턴을 존중하면서도 월내 안전 제약을 유지
- 동일 입력에서 메인/폴백 결과 일관성 향상

---

## 4) 검증 포인트
- 케이스 A: 전월 말이 1N 유발 패턴, 익월 day0 N 고정 필요
  - 결과: day0 예외 스킵으로 생성 가능
- 케이스 B: 일반 월중 단발 N
  - 결과: 기존처럼 1N 금지 정상 적용
- 케이스 C: fallback 진입
  - 결과: 메인과 동일한 day0 예외 처리

---

## 5) 주의사항
- 본 수정은 1N 금지 규칙을 폐기한 것이 아니라, **월경계 강제 N에 대한 최소 예외**만 도입한 것이다.
- day0 예외 범위를 확장하면 규칙 완화로 오해될 수 있으므로, 현재 범위를 유지하는 것이 안전하다.
