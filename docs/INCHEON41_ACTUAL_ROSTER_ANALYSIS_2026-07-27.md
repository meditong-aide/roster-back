## 3. ★ 메모리/기존 조사 대비 정정 2건

### 정정 1 — 요구 #10 은 "DE 코드 부재"가 아니다

기존 해석: *"10번은 `DE` 결합코드가 이 병동에 없음 · 같은날 D+E 는 `AddExactlyOne` 로 구조상 불가"* → **오독**.

원문은 **"DE근무 다음날 D근무 금지"**이고, `DE` 는 실재하는 **단일 근무코드**다
(파트장 종미영 7월 17회·8월 20회, 선임 윤지선 7월 12회·8월 14회 사용).
"같은 날 D와 E를 동시에" 가 아니라 **주간~저녁을 걸치는 하나의 근무형**이다.

→ 재정의 대상이 아니라 **정상 요구**이며, 필요한 것은
① `shifts` 에 `DE` 코드 등록(현재 그룹 12종에 없음) ② `DE → D` 금지 제약 추가.
D 커버리지 계산에 DE 를 포함할지도 함께 결정해야 한다(요구 "D근무 파트장포함 최소 5명"은 포함 전제).

### 정정 2 — 요구 #3 은 논리모순이 아니다

기존 해석: *"3번은 1번과 논리모순(1번=1N금지 vs 3번=1N존재 전제)"*.

원문 조합을 보면 **1N 예외 완화 규칙**으로 읽는 것이 자연스럽다.
- #1 "N근무 연속 2개 미만 / 3개 초과 금지" = 원칙적으로 2~3연속만
- #2 "N근무 후 OFF 2개 필수"
- #3 "N근무 1개 후 OFF E 근무 가능" = **1N 이 발생한 경우엔 OFF 2개가 아니라 OFF 1개 후 E 근무 허용**

실측 뒷받침: 8월 1N 단독은 **2건뿐이고 둘 다 월 경계**(정윤정 8/31, 윤혜수 8/1)다.
즉 월 경계에서 잘린 N 시퀀스를 처리하는 규칙일 가능성이 높다. 최종 확인은 병원 몫이지만,
"모순이라 재정의 필요"보다는 **"1N 예외 처리 규칙"으로 구현 가능**하다.

## 4. ★ 하드제약 재현가능성 — 실제 운영표는 전부 통과

2026-08 확정 근무표(25명 × 31일)를 CLAUDE.md 하드락 기준으로 전수 검사한 결과:

| 검사 | 결과 |
|---|---|
| 연속근무 6일 이상 | **0건** (최대 5일) |
| N → D 전환 | **0건** |
| E → D 전환 | **0건** |
| N → E 전환 | **0건** |
| DE → D 전환 (요구 #10) | **0건** |
| N 4연속 이상 | **0건** |
| 2N/3N 후 OFF 2개 미충족 | **0건** |
| 월 N 15회 초과 | **0건** |
| 1N 단독 | 2건 — **둘 다 월 경계**(8/1, 8/31) |

→ **요구를 전부 하드 제약으로 걸어도 실현 가능한 해가 존재한다**는 실증. 하드락 유지 근거가 된다.

### 예외: 요구 #14(조별 선임 포함)는 hard 부적합

"D,E,N 근무시 각조에서 1,2번째 간호사가 1명은 포함" 을 팀 내 순번 1·2번으로 해석해 검사하면,
**실제 운영표 자체가 위반**한다.

| 근무 | 선임(각조 1·2번) 0명인 날 |
|---|---|
| D | 3일 (8/4, 8/5, 8/31) |
| E | 1일 (8/30) |
| N | **8일** (8/11·12·17·18·19·20·21·22) |

N 은 4명 정원인데 N전담 2명이 매일 절반을 차지하므로 선임 포함이 구조적으로 어렵다.
→ **hard 로 걸면 infeasible 위험**. soft(가중치) 또는 D/E 한정 적용을 권고한다.
(기존 조사에서 "#12 hard화는 시뮬 후 결정" 으로 둔 판단이 옳았고, 실데이터가 soft 쪽을 지지한다.)

## 5. 개별 요구 구현 힌트 (실측 기반)

### #6 "N근무 15개 후 수면 휴가 1개" — 즉시가 아니다

| 간호사 | N15 도달일 | 수면휴가 배정일 | 간격 |
|---|---|---|---|
| 권현은 | 8/22 | 8/29 | 7일 |
| 정수영 | 8/14 | 8/17 | 3일 |
| 장선희 | 8/5 | 8/11 | 6일 |
| 김효경 | 8/19 | 8/24 | 5일 |
| 윤혜수 | 8/27 | 8/30 | 3일 |
| 조형민 | 8/24 | 8/28 | 4일 |

N15 직후가 아니라 **3~7일 뒤 임의 시점**에 부여된다. 기존 Phase3 설계의
**"A안 후처리(생성 후 OFF 1개를 `수면` 코드로 치환)"** 가 실제 운영과 부합한다.
또한 N 번호는 15에서 1로 롤오버(N15 → N1)하는 **누적 카운터**이며 월 경계를 넘어 이어진다.

### #13 단축근무 — 명목 4회, 실제 3~5회당 1개

최수진B 8월: 근무 15일 · 단축 4회(8/10, 8/14, 8/24, 8/29).
직전 단축 이후 근무 횟수는 4 → 3 → 5 → 3 으로 흔들린다. 7월은 단축 1회뿐.
엄격한 "4일 주기" 하드 제약보다 **근무 4회당 1개(누적, 오차 허용)** 로 모델링하는 편이 안전하다.

### 임산부 = 최수진A · 최수진B

둘 다 7·8월 **N=0** 이고 산전휴가를 사용한다. DB `allowed_shifts=["D","E"]` 로 이미 반영돼 있다.
요구 "임산부(N제외)" 는 **추가 조치 불필요**.

### 주휴·보건

전원 OFF 11개(N전담만 16개), 보건휴가 월 1회 — `off_days=11` 현행값과 일치.

### 원티드 반영률 96.2%

8월 신청 132건 중 127건 반영. 미반영 5건은 산전휴가·단축휴가·N제외 등 제도적 사유다.
운영자가 원티드를 거의 그대로 수용하고 있으므로, 생성기도 원티드 충족을 높게 잡아야 자연스럽다.
