## ★ 스캐너 주의점 1 — 괄호 표기 (2026-08-03 수정)

`N(B)5` · `D(B)` 같은 **타 팀 지원 표기**를 제거하지 않으면 연번·근무코드 정규식이
전부 빗나가 그 셀이 통째로 누락된다. `norm()` 에서 `re.sub(r"\([^)]*\)", "", s)` 로 제거한다.

★ 이 처리가 빠져 있어 41병동 8월 5명의 N 개수가 DB 와 어긋났고,
**권현은은 N15 도달 자체를 놓쳤다**(`N11 N12 N13 N14 N(B)15 N(B)1` → N14 로 오판).
단순 개수 오차가 아니라 **수면OFF 판정이 뒤집히는** 문제다.

## ★ 스캐너 주의점 2 — 헤더/데이터 열 어긋남

**헤더의 날짜 열과 데이터의 날짜 열이 한 칸 어긋난 시트가 있다**(41병동 7월).

```
헤더  r3:  c2='7월'  c3=1  c4=2 …
데이터 r5: c2='팀'   c3='종미영'  c4='DE'(1일)   ← 이름이 c3
```

헤더를 믿고 `dcol` 을 고정하면 한 칸씩 밀려 읽는다. 행마다 근무코드가 가장 많이 잡히는
시작열을 고르는 방식으로 보정했다(`scan_sheet` 내 `best_dcol`).

이를 놓치면 **N 연번 월경계 연속률이 25.7% 로 잘못 나온다**(실제 94.7%).

## ★ 앵커 재산출 — DB 를 레퍼런스로 삼는다

`night_cycle_seed.json` 은 엑셀에서 뽑지만, **정본 판정은 DB 확정본이 한다.**

```
① 같은 사람이 여러 파일에 있다      (보고용) 14건 / AI본 15건 → DB=14 가 정답
② 동명이인은 병동명으로 못 가른다    응급실-RN 김지영 ↔ 응급실-AN 김지영
③ 이름 표기가 흔들린다             '이  솔'(공백2) · '김지영b' · '황상은(파트장)'
```

→ 셋 다 **DB 의 8월 N 개수**(`schedule_entries`)를 기준으로 해소한다.
   재산출 스크립트가 후보 중 DB 와 N 개수가 맞는 레코드를 고른다.

결과: **227명 · DB 대조 100% 일치 · 미포함 0명**
(수정 전에는 170명 97.1% 였고 41병동 5명이 어긋나 있었다)

미매칭 4명은 **DB 미등록자**라 정상이다 — 강성진·송수빈·최종현·김경근.
